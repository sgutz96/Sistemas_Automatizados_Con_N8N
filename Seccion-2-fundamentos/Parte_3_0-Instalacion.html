🎓

Estás aprendiendo

Usa n8n Cloud. Sin fricción, sin setup. Enfócate en el workflow, no en el servidor.

🚀

n8n Cloud — Setup

La forma más rápida de empezar con n8n. Sin instalación, sin servidor, sin configuración técnica.

☁️ URL oficial: https://app.n8n.cloud — El trial gratuito dura 14 días, sin tarjeta de crédito requerida.
📋 Pasos para crear tu cuenta Cloud
1

Ir a app.n8n.cloud

Abre tu navegador y navega a https://app.n8n.cloud. Haz clic en "Start for free" o "Sign up".

2

Crear cuenta con email o Google

Usa tu email de trabajo o tu cuenta de Google. Recibirás un email de verificación — confírmalo antes de continuar.

3

Elegir nombre de instancia

Se te pedirá un nombre para tu instancia. Por ejemplo: mi-empresa. Tu URL quedará así: mi-empresa.app.n8n.cloud

4

Elegir región y plan

Selecciona la región más cercana (normalmente US East o EU West). Para empezar, elige el plan Starter o el trial gratuito. No se requiere tarjeta.

5

¡Listo! Acceder al dashboard

En menos de 2 minutos tu instancia estará activa. Serás redirigido al editor de workflows. Aquí empieza todo.

Sección 4

Docker — Instalación

La forma más robusta y recomendada de instalar n8n en local o en un servidor. Un solo comando y tienes n8n corriendo de manera aislada y portable.

🐳 Prerequisito: necesitas Docker instalado en tu máquina. Descárgalo en https://docker.com/get-started — disponible para Mac, Windows y Linux.
🔍 Verificar que Docker está instalado
Terminal
# Verificar versión de Docker docker --version # → Docker version 24.x.x, build xxxxxxx # Verificar que Docker Desktop está corriendo docker ps # → Debe mostrar la lista de contenedores (vacía si es la primera vez)
🚀 Opción 1 — Comando rápido (desarrollo)

Un solo comando para empezar

Perfecto para aprender y probar. Los datos se pierden si el contenedor se elimina.

Terminal
docker run -it --rm \ --name n8n \ -p 5678:5678 \ docker.n8n.io/n8nio/n8n # Luego abrir en el navegador: http://localhost:5678
🏭 Opción 2 — Con persistencia (recomendado)

Datos guardados aunque reinicies el contenedor

Usa un volumen Docker para que tus workflows y credenciales se guarden de forma permanente.

Terminal — Mac / Linux
# Crear volumen para persistir datos docker volume create n8n_data # Correr n8n con el volumen montado docker run -d \ --name n8n \ -p 5678:5678 \ -v n8n_data:/home/node/.n8n \ --restart unless-stopped \ docker.n8n.io/n8nio/n8n
Terminal — Windows (PowerShell)
docker volume create n8n_data docker run -d ` --name n8n ` -p 5678:5678 ` -v n8n_data:/home/node/.n8n ` --restart unless-stopped ` docker.n8n.io/n8nio/n8n
📋 Opción 3 — Docker Compose (nivel pro)

Con archivo docker-compose.yml

La forma más ordenada y escalable. Crea el archivo docker-compose.yml en una carpeta vacía:

version: '3.8' services: n8n: image: docker.n8n.io/n8nio/n8n container_name: n8n restart: unless-stopped ports: - "5678:5678" volumes: - n8n_data:/home/node/.n8n environment: - N8N_BASIC_AUTH_ACTIVE=true - N8N_BASIC_AUTH_USER=admin - N8N_BASIC_AUTH_PASSWORD=tu_password - GENERIC_TIMEZONE=America/Bogota volumes: n8n_data:
Levantar con Docker Compose
# Levantar en segundo plano docker compose up -d # Ver logs docker compose logs -f # Detener docker compose down
🔧 Comandos útiles de Docker
▶️
docker start n8n — iniciar contenedor detenido
⏹️
docker stop n8n — detener contenedor
🔄
docker restart n8n — reiniciar contenedor
📋
docker logs n8n -f — ver logs en tiempo real
🔍
docker ps — ver contenedores activos
🗑️
docker rm -f n8n — eliminar contenedor (datos en volumen se conservan)
Sección 5

npm — Instalación Local

La instalación más directa si ya tienes Node.js en tu máquina. Sin Docker, sin complicaciones — ideal para desarrollo y pruebas rápidas.

📦 Prerequisito: necesitas Node.js versión 18 o superior. Descárgalo en https://nodejs.org — descarga la versión LTS.
🔍 Verificar prerequisitos
Terminal
# Verificar Node.js (requiere v18+) node --version # → v20.x.x ✓ # Verificar npm npm --version # → 10.x.x ✓
⚡ Instalación con npx (sin instalar globalmente)

La forma más rápida — cero instalación previa

Con npx ejecutas n8n directamente sin instalarlo de forma permanente. Perfecto para probar.

Terminal
# Ejecutar n8n directamente con npx npx n8n # Esperar a que aparezca en la terminal: Editor is now accessible via: http://localhost:5678 # Abrir en el navegador → localhost:5678
🏠 Instalación global (uso permanente)

Instalar n8n como comando disponible siempre

Terminal
# Instalar n8n globalmente npm install n8n -g # Puede tardar 2-5 minutos. Cuando termine: # Iniciar n8n n8n start # Para que corra en background (Mac/Linux) n8n start & # Abrir en el navegador http://localhost:5678
✅ Ventajas de npm
  • ✓No necesita Docker
  • ✓Setup en un solo comando
  • ✓Integra fácil con el entorno local
  • ✓Rápido para desarrollo
⚠️ Limitaciones de npm
  • ✗Menos aislado que Docker
  • ✗Depende de la versión de Node del sistema
  • ✗Más difícil de escalar en producción
  • ✗No auto-reinicia si el proceso muere
💡 Recomendación: para aprender usa npx n8n — es el comando más rápido. Si quieres usarlo de manera regular en tu máquina local, instálalo globalmente con npm. Para producción, usa Docker o Cloud.

Configuración Inicial

Una vez que n8n está corriendo, hay 5 configuraciones esenciales que debes hacer antes de construir tu primer workflow real.

👤 Paso 1 — Crear usuario administrador

La primera vez que abres n8n en local, te pedirá crear el usuario principal. Este usuario tiene acceso total a la instancia.

Datos requeridos
📧
Email de administrador
🔑
Contraseña segura (+12 caracteres)
👤
Nombre y apellido
Buenas prácticas
✅
Usa email real, no temporal
✅
Guarda la contraseña en un gestor
✅
Este email recibirá alertas del sistema
🌍 Paso 2 — Variables de entorno clave

Configuración avanzada para instalaciones locales

Agrega estas variables en tu docker-compose.yml o como variables del sistema:

GENERIC_TIMEZONE
America/Bogota — zona horaria para schedules y logs
N8N_HOST
localhost o tu dominio si usas servidor externo
N8N_PORT
5678 — puerto por defecto, cámbialo si hay conflicto
N8N_ENCRYPTION_KEY
Clave para encriptar credenciales guardadas. Genera una aleatoria y guárdala en lugar seguro.
N8N_BASIC_AUTH_ACTIVE
true — activa autenticación básica HTTP (importante si expones al exterior)
WEBHOOK_URL
URL pública si usas un servidor o ngrok. Necesaria para que los webhooks externos funcionen.
🔐 Paso 3 — Configurar credenciales

Las credenciales se guardan en n8n de forma encriptada. Las usarás en los nodos para conectar servicios.

1

Ir a Settings → Credentials

En el menú lateral izquierdo, haz clic en el ícono de llave o en "Credentials" en el menú de Settings.

2

Crear nueva credencial

Clic en "Add Credential" → busca el servicio (Gmail, Slack, Google Sheets, etc.) → ingresa los datos de acceso.

3

Probar y guardar

Usa el botón "Test" para verificar que la conexión funciona antes de guardar. n8n confirma con un mensaje verde.

🔗 Paso 4 — Configurar ngrok (webhooks locales)

Para recibir webhooks externos en tu instalación local, necesitas exponer el puerto 5678 al internet. ngrok lo hace en segundos.

# Instalar ngrok (Mac con Homebrew) brew install ngrok # Exponer n8n al exterior ngrok http 5678 # Copiar URL generada (ejemplo): https://abc123.ngrok.io # Usarla como WEBHOOK_URL
⚙️ Paso 5 — Settings de n8n

Revisa estas opciones dentro de la interfaz de n8n antes de empezar:

  • ✓Zona horaria correcta configurada
  • ✓Email de notificaciones configurado
  • ✓Límite de historial de ejecuciones
  • ✓Modo de guardado automático activado
  • ✓Community nodes activados si necesitas más nodos

Sección 8

Primera Prueba Real

n8n está instalado y configurado. Ahora verificamos que todo funciona correctamente con una prueba end-to-end.

🎯 Objetivo: ejecutar el workflow de la Seccion 2 (Lead Capture) en tu nueva instalación y confirmar que responde correctamente. Si lo haces funcionar aquí, tu entorno está 100% listo.
🔄 Importar el workflow de Seccion 2
1

Abrir n8n en el navegador

Cloud: https://tu-instancia.app.n8n.cloud — Local: http://localhost:5678

2

Importar el archivo JSON

En la pantalla principal de Workflows → clic en el menú ⋯ → "Import from file" → selecciona primer-workflow.json

3

Verificar los nodos

Confirma que aparecen los 3 nodos: Webhook → SET → Respond to Webhook. Todos conectados en ese orden.

4

Activar el workflow

Haz clic en el toggle superior derecho. El indicador cambia a verde: ● Active. Copia la URL del webhook que aparece en el nodo.

🧪 Probar con cURL o Postman
# Reemplaza la URL con la de tu webhook curl -X POST \ https://tu-instancia/webhook/lead-capture \ -H "Content-Type: application/json" \ -d '{"name": "Carlos", "email": "carlos@email.com"}' # Respuesta esperada: { "message": "Lead recibido correctamente" }
1

Abrir Postman → New Request

Selecciona método POST y pega la URL del webhook.

2

Body → raw → JSON

Selecciona "Body" → "raw" → en el dropdown elige "JSON" y pega el payload.

3

Send → verificar respuesta

Haz clic en Send. Deberías ver el mensaje de confirmación con status 200 en el panel de respuesta.

import requests url = "https://tu-instancia/webhook/lead-capture" payload = { "name": "Carlos", "email": "carlos@email.com" } response = requests.post(url, json=payload) print(response.json()) # → {'message': 'Lead recibido correctamente'}
✅ Señales de éxito
  • ✓La petición devuelve status 200
  • ✓El JSON de respuesta es correcto
  • ✓En n8n aparece ejecución exitosa (verde)
  • ✓Puedes ver los datos en cada nodo del historial
🚫 Si algo falla — primeros pasos
  • ✗¿El workflow está activado (toggle verde)?
  • ✗¿La URL del webhook es correcta?
  • ✗¿Enviaste Content-Type: application/json?
  • ✗¿n8n está corriendo? (verifica localhost:5678)
Sección 9

Errores Comunes

Los errores más frecuentes durante la instalación de n8n. Organizados por tipo para que los encuentres rápido.

🐳 Errores de Docker
  • ✗
    "Port 5678 is already in use"
    Otro proceso usa ese puerto. Solución: docker stop n8n o cambia el puerto en el comando: -p 5679:5678 y abre localhost:5679.
  • ✗
    "Cannot connect to Docker daemon"
    Docker Desktop no está corriendo. Abre la aplicación Docker Desktop en tu sistema y espera a que inicie completamente.
  • ✗
    Contenedor se detiene inmediatamente
    Revisa los logs: docker logs n8n. El problema más común es una variable de entorno mal escrita o un volumen con permisos incorrectos.
  • ✗
    Los datos desaparecen al reiniciar
    Olvidaste montar el volumen. Asegúrate de incluir -v n8n_data:/home/node/.n8n en el comando de Docker.
📦 Errores de npm
  • ✗
    "node: command not found"
    Node.js no está instalado. Descarga la versión LTS desde nodejs.org e instala. Luego reinicia la terminal.
  • ✗
    "npm WARN deprecated" al instalar
    Son advertencias, no errores críticos. La instalación continúa. Si aparece "npm ERR!" sí es un problema — verifica la versión de Node.
  • ✗
    n8n se detiene al cerrar la terminal
    El proceso muere cuando cierras la terminal. Usa n8n start & o instala pm2 para mantenerlo corriendo en background.
🌐 Errores de webhooks y red
  • ✗
    Webhook no recibe datos externos
    En instalación local, los servicios externos no pueden alcanzar localhost. Usa ngrok para exponer el puerto: ngrok http 5678 y configura esa URL como WEBHOOK_URL.
  • ✗
    Error 404 al llamar el webhook
    El workflow no está activo. Verifica que el toggle en el editor esté en verde (Active). Si está en test mode, el webhook solo responde dentro del editor.
  • ✗
    Error de CORS en el navegador
    Agrega el encabezado N8N_CORS_ORIGINS=* como variable de entorno, o configura el dominio específico que necesita acceder.
🔍 Regla de oro para debugging: ante cualquier error, lo primero es revisar los logs. En Docker: docker logs n8n -f. En npm: los mensajes aparecen directo en la terminal. El 90% de los problemas se resuelven con la información del log.
Sección 10

Buenas Prácticas

Lo que separa una instalación amateur de una instalación profesional. Aplica estas prácticas desde el día 1.

🔒 Seguridad
  • ✓
    Siempre usa autenticación
    Nunca expongas n8n al internet sin N8N_BASIC_AUTH_ACTIVE=true o sin un proxy con autenticación. Una instancia abierta es un riesgo real.
  • ✓
    Guarda la N8N_ENCRYPTION_KEY
    Si pierdes esta clave, pierdes acceso a todas tus credenciales guardadas. Guárdala en un gestor de contraseñas como 1Password o Bitwarden.
  • ✓
    Usa HTTPS en producción
    En local está bien usar HTTP. Pero si despliegas en un servidor, configura SSL/TLS con un certificado (Let's Encrypt es gratuito) y un proxy como nginx.
  • ✓
    Rota las credenciales periódicamente
    Los API keys de servicios externos deben rotarse cada 90 días o cuando sospechas una filtración. n8n lo hace fácil desde Credentials.
💾 Backups y mantenimiento
  • ✓
    Exporta tus workflows regularmente
    Descarga el JSON de cada workflow importante al menos una vez por Seccion. Si algo falla, los restauras en minutos sin perder trabajo.
  • ✓
    Haz backup del volumen Docker
    El volumen n8n_data contiene workflows, credenciales e historial. Cópialo periódicamente o sincronízalo con una herramienta de backup.
  • ✓
    Mantén n8n actualizado
    Revisa las release notes antes de actualizar. Para Docker: docker pull docker.n8n.io/n8nio/n8n y reinicia el contenedor.
🗂️ Organización desde el inicio
  • ✓
    Nombra los workflows de forma clara
    Usa un formato consistente: [Sistema] — Función — Versión. Ejemplo: "CRM — Lead Capture v2". Evita nombres genéricos como "Workflow 1".
  • ✓
    Usa tags para categorizar
    n8n permite agregar tags a los workflows. Crea tags como "producción", "testing", "marketing", "ventas" para filtrar rápido.
  • ✓
    Documenta con notas en el canvas
    Agrega notas (Sticky Notes) explicando qué hace cada sección del workflow. Tu yo del futuro te lo agradecerá.
  • ✓
    Separa entornos dev y prod
    Si puedes, ten una instancia de testing y una de producción. Prueba siempre en testing antes de activar en producción.
🚀 Nivel pro — configuraciones avanzadas

🔁 pm2 para npm (auto-restart)

# Instalar pm2 globalmente npm install pm2 -g # Iniciar n8n con pm2 pm2 start n8n -- start # Auto-inicio al reiniciar el sistema pm2 startup pm2 save
