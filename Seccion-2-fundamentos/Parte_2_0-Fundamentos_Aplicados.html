Sección 2

Conceptos Clave

Antes de tocar n8n, necesitas entender los cuatro bloques de construcción de cualquier automatización.

🔄

Workflow

Flujo de automatización compuesto por nodos conectados. Es el "plano" que define qué pasa, en qué orden y con qué datos en cada etapa.

⚡

Trigger

Evento que inicia el flujo. Sin trigger, no hay automatización. Puede ser un webhook, un formulario, un nuevo email, o un horario programado.

🧩

Nodo

Unidad que procesa o transforma datos dentro del flujo. Cada nodo tiene una función específica: filtrar, formatear, enviar, guardar, condicionar.

🎯

Acción

Resultado ejecutado por el sistema al final del flujo. Es el "qué hace" el workflow: enviar una respuesta, guardar en base de datos, enviar un mensaje.

Sección 3

Componentes de n8n

n8n tiene tres tipos de bloques. Entenderlos te da el control total para construir cualquier automatización.

1 — Trigger (disparador)

Inicia el flujo automáticamente

Sin trigger no hay workflow. Es el punto de entrada que activa toda la cadena de automatización.

Webhook
Formulario
Nuevo email
Schedule
💡 Esta Seccion: usaremos el Webhook como trigger. Es el más versátil y el que más vas a usar en proyectos reales.
2 — Nodos (procesamiento)

Transforman y enrutan los datos

Son el cerebro del workflow. Cada nodo recibe datos de entrada, hace algo con ellos y los pasa al siguiente paso.

SET
Crea o modifica campos en el objeto de datos. Ideal para organizar la información que llega del trigger.
IF
Evalúa una condición y bifurca el flujo en dos caminos: verdadero o falso. Agrega lógica condicional.
Function
Permite escribir JavaScript personalizado. Para lógica avanzada que los nodos estándar no cubren.
3 — Acciones (salida)

Ejecutan tareas en el mundo real

Son los nodos de salida. Aquí el workflow hace algo concreto: envía datos, guarda información o notifica a alguien.

Enviar email
Google Sheets
Slack / Telegram
Respond Webhook

Crear tu primer workflow funcional. Objetivo: construir un flujo que reciba datos y responda automáticamente.

🚀 Objetivo: construir un workflow que reciba un nombre y email vía webhook, procese esa información y devuelva una respuesta automática. Sin código, en menos de 15 minutos.

📋 Instrucciones del ejercicio

4 pasos para tu primer workflow

1

Crear un webhook en n8n

Agrega el nodo Webhook, configura el método como POST y activa el workflow para obtener la URL. Esta URL es tu punto de entrada.

2

Recibir datos — nombre y email

El webhook acepta cualquier cuerpo JSON. En este ejercicio, espera recibir name y email en el body de la petición.

3

Procesar con nodo SET

Agrega el nodo SET para reorganizar y etiquetar los datos. Define los campos name y email tomándolos del input del webhook.

4

Enviar respuesta automática

Agrega el nodo "Respond to Webhook" con el mensaje "Lead recibido correctamente". Conecta los tres nodos y ejecuta el flujo.

Sección 7

Errores Comunes

Los errores más frecuentes al construir el primer workflow. Conocerlos de antemano te ahorra horas de debugging.

🚫 Errores que debes evitar
  • ✗
    No activar el workflow
    El webhook no responde si el workflow está en modo "test" solamente. Debes activarlo con el toggle para que funcione en producción.
  • ✗
    No ejecutar el webhook correctamente
    Usar GET en lugar de POST, o no enviar el Content-Type correcto. Siempre usa POST con Content-Type: application/json.
  • ✗
    Conexiones incorrectas entre nodos
    Nodos desconectados o conectados en el orden equivocado. Siempre: Webhook → SET → Respond to Webhook. El orden importa.
  • ✗
    No probar con datos reales
    Probar sin enviar datos al webhook da errores vacíos. Siempre incluye el body JSON completo al hacer la prueba.
  • ✗
    No entender el flujo de datos
    Usar variables incorrectas en el nodo SET porque no se verificó qué estructura tiene el JSON que llega del webhook.
✅ Buenas prácticas
  • ✓
    Mantener workflows simples
    Un workflow hace una cosa bien. No intentes resolver 5 problemas en un solo flujo al inicio.
  • ✓
    Nombrar nodos claramente
    "Webhook Lead Capture", "SET Name Email", "Respond Success". Nombres descriptivos evitan confusión al escalar.
  • ✓
    Probar cada nodo individualmente
    Ejecuta el workflow nodo por nodo en modo test. No asumas que todo funciona sin verificarlo.
  • ✓
    Validar datos de entrada
    Verifica la estructura del JSON que llega antes de referenciar campos en el nodo SET.
  • ✓
    Documentar el flujo
    Agrega notas en n8n a cada nodo. Un workflow sin documentación es difícil de mantener o mejorar en el futuro.
🚀 Nivel pro — bonus

🔀 Agregar validación con nodo IF
