Nodos Principales en n8n

Los nodos son las piezas de LEGO de cualquier workflow. Cada uno hace una cosa específica. Encadenados, construyen automatizaciones complejas.

🧠 La regla fundamental

Cada nodo recibe datos → los transforma → los pasa al siguiente

No importa qué tan complejo sea el workflow: todos los nodos funcionan bajo esta misma lógica. Entender eso es entender n8n.

Nodo 1 de 7

Nodo Set

El nodo más usado en n8n. Define, renombra, elimina o fija valores en los datos que pasan por el workflow.

🔧
Set · Transformación de datos
Reorganiza y define campos
Toma los datos que llegan y los reescribe como tú necesitas. Puedes crear campos nuevos, renombrar existentes, fijar valores estáticos o construir cadenas combinando múltiples campos. Sin código, con interfaz visual.
📝 Crear campos ✏️ Renombrar 🗑️ Eliminar campos 🔗 Combinar valores 🔢 Valores estáticos
⚙️ Cómo funciona — entrada vs salida
📥 Llega del webhook
{ "nombre": "Laura", "email": "laura@x.com", "telefono": "3001234567", "fuente": "web" }
→
📤 Sale del Set
{ "mensaje": "Nuevo lead: Laura", "contacto": "laura@x.com", "origen": "Formulario web" }
📌 Cuándo usar Set
✅
Formatear datos antes de enviarlos a otro nodo
✅
Construir mensajes combinando varios campos en uno
✅
Añadir metadatos como timestamp, estado, origen
✅
Limpiar datos eliminando campos innecesarios
❌
No usar para lógica compleja — para eso está Function
⚙️ Ejemplos de expresiones en Set
// Campo simple — tomar valor del nodo anterior nombre → {{$json.nombre}} // Combinar varios campos en un string mensaje → "Hola " + {{$json.nombre}} + ", tu pedido llegará en 3 días" // Valor estático (siempre el mismo) estado → "pendiente" // Timestamp actual fecha → {{$now}} // Transformar a mayúsculas pais → {{$json.pais.toUpperCase()}} // Acceder a dato anidado ciudad → {{$json.direccion.ciudad}}
💡
Tip pro: activa "Keep Only Set" para que el nodo elimine todos los campos originales y solo pase los que tú defines. Mantiene el JSON limpio.
⚠️
Error común: olvidar el prefijo $json. al referenciar campos. Si el campo dice "nombre" debes escribir {{$json.nombre}}.

Nodo Function

Cuando Set no es suficiente. Escribe JavaScript puro para transformar, filtrar, calcular o generar cualquier dato que necesites.

⚡
Function · Código JavaScript
Lógica personalizada sin límites
El nodo Function te da acceso completo a JavaScript dentro del workflow. Puedes manipular arrays, hacer cálculos, filtrar elementos, formatear fechas, generar IDs únicos, construir estructuras complejas o cualquier transformación que imagines.
💻 JavaScript 🧮 Cálculos 📋 Manipular arrays 🔄 Transformar 🎯 Filtrar items
⚙️ Estructura básica del Function
// Los items llegan como array // Debes retornar siempre un array const items = $input.all(); const result = []; for (const item of items) { const data = item.json; result.push({ json: { nombre: data.nombre, email: data.email.toLowerCase(), mensaje: `Hola ${data.nombre}, bienvenido`, timestamp: new Date().toISOString(), id: Math.random().toString(36).slice(2) } }); } return result;
🧪 Casos de uso reales
// 1. Calcular descuento según monto const monto = data.total; const descuento = monto > 500000 ? monto * 0.15 : monto * 0.05; // 2. Formatear fecha en español const fecha = new Date(data.fecha) .toLocaleDateString('es-CO'); // 3. Filtrar solo leads válidos if (!data.email.includes('@')) { return []; // descarta el item } // 4. Construir payload para API const payload = { to: data.email, subject: `Pedido #${data.id}`, body: data.mensaje };
📌 Set vs Function — ¿cuándo usar cada uno?
SituaciónUsar
Renombrar camposSet
Combinar 2-3 campos en textoSet
Valor fijo siempre igualSet
Cálculos matemáticosFunction
Lógica condicional en datosFunction
Manipular arrays / listasFunction
Generar IDs / hashesFunction
💡
Acceso a datos: usa $input.all() para todos los items, $input.first() para el primero, o $input.item.json dentro del loop.
⚠️
Siempre retorna array: aunque sea un solo objeto, debe ir dentro de [ { json: {...} } ]. Si retornas vacío [], el workflow se detiene.

Nodo IF

El nodo que le da inteligencia al workflow. Evalúa una condición y divide el flujo en dos caminos: verdadero o falso.

🔀
IF · Lógica condicional
Dos caminos según una condición
El nodo IF evalúa si una condición es verdadera o falsa, y manda los datos por el camino correspondiente. Es el "si esto, entonces aquello" de tus workflows. Sin IF, todos los datos siguen el mismo camino siempre.
✅ Rama true ❌ Rama false 🔢 Comparar números 📝 Comparar texto 📋 Comparar listas

🏢 Casos de uso reales
🛍️
E-commerce: ¿es cliente VIP? → notificación prioritaria vs normal
📧

📦

💳

🌍

🔗 Múltiples condiciones — AND / OR
// AND: ambas condiciones deben cumplirse monto > 500000 AND estado == "aprobado" → true solo si el monto ES mayor Y el estado ES aprobado // OR: basta con que una se cumpla pais == "CO" OR pais == "MX" → true si es de Colombia O de México
Nodo 4 de 7

Nodo Switch

El IF con superpoderes. Cuando necesitas más de dos caminos, Switch crea tantas rutas como necesites según el valor de un campo.

🎛️
Switch · Enrutamiento múltiple
Múltiples rutas según un valor
Evalúa el valor de un campo y dirige los datos por la salida correspondiente. En vez de anidar muchos IFs, Switch lo resuelve en un solo nodo. Perfecto para enrutar por tipo de producto, país, estado, categoría o cualquier campo discreto.
🛣️ N rutas 📋 Por valor exacto 🏷️ Por categoría 🌍 Por país / región 📦 Por tipo
⚙️ IF vs Switch — el mismo problema, distinta escala
❌ Con IF anidados (difícil de mantener)
IF pais == "CO" → flujo Colombia ELSE IF pais == "MX" → flujo México ELSE IF pais == "AR" → flujo Argentina ELSE → flujo genérico // 3 nodos IF encadenados = pesadilla
✅ Con Switch (limpio y escalable)
SWITCH pais: "CO" → salida 1 → flujo Colombia "MX" → salida 2 → flujo México "AR" → salida 3 → flujo Argentina otros → salida 4 → flujo genérico // 1 solo nodo, fácil de leer y editar
🏢 Casos reales con Switch
📦
Tipo de pedido: "normal" / "express" / "internacional" → cada uno con su flujo de envío distinto
🎫
Categoría de ticket: "facturación" / "soporte técnico" / "ventas" → asignar al equipo correcto
💼
Plan de suscripción: "free" / "pro" / "enterprise" → activar funciones distintas
🌎
Región: "LATAM" / "US" / "EU" → precios, idioma y condiciones distintas
📌 ¿IF o Switch?
SituaciónUsar
2 caminos (sí/no)IF
Condición numéricaIF
3 o más caminosSwitch
Enrutar por categoríaSwitch
Reemplazar IFs anidadosSwitch
Nodo 5 de 7

HTTP Request

El nodo que conecta n8n con cualquier API del mundo. Si tiene una URL y acepta HTTP, puedes integrarlo en tu workflow.

🌐
HTTP Request · Integración con APIs externas
Llama a cualquier API desde el workflow
HTTP Request hace peticiones GET, POST, PUT, DELETE a cualquier endpoint. Puedes enviar datos, recibir respuestas y usarlas en los siguientes nodos. Es el puente entre n8n y cualquier servicio externo que tenga API REST.
📡 GET / POST / PUT 🔑 Auth: Bearer / API Key 📦 Body JSON 📥 Procesa respuesta 🔗 Cualquier REST API
⚙️ Configuración del nodo
// Configuración básica Método: POST URL: https://api.ejemplo.com/clientes Auth: Bearer Token → {{$env.API_KEY}} // Body (lo que envías) Content-Type: application/json { "nombre": "{{$json.nombre}}", "email": "{{$json.email}}", "origen": "n8n-workflow" } // Respuesta que llega al nodo siguiente { "id": "clt_8f3a9b", "status": "created" }
🏢 Ejemplos de integraciones reales
🤖
OpenAI / Claude: enviar texto → recibir respuesta generada por IA dentro del workflow
💳
Wompi / Stripe: consultar estado de pago por ID de transacción
📍
Google Maps: geocodificar una dirección y obtener coordenadas
📱
WhatsApp Business: enviar mensaje al número del cliente via API de Meta
🏦
API del banco: consultar saldo o registrar movimiento contable
🔑 Tipos de autenticación soportados
TipoCuándo usarlo
Sin authAPIs públicas (clima, divisas)
API Key en headerLa mayoría de SaaS modernos
Bearer TokenOAuth2, JWT, APIs modernas
Basic AuthSistemas legacy, ERPs
OAuth2Google, Microsoft, Salesforce
🔒
Buena práctica: nunca pongas API keys directamente en el nodo. Usa las credenciales de n8n o variables de entorno ($env.MI_API_KEY). Así el key no queda expuesto en el workflow.
Nodo 6 de 7

Nodo Merge

Une dos ramas del workflow en una sola. Indispensable cuando divides el flujo con un IF o Switch y necesitas reunirlo después.

🔗
Merge · Unión de flujos
Junta múltiples ramas en una
Cuando el flujo se divide (por un IF, Switch o ramas paralelas), Merge lo vuelve a unir. Puede combinar datos de ambas ramas, esperar a que lleguen todos los items, o simplemente pasar los datos de la primera rama que llegue.
🔀 Une ramas ⏳ Espera ambas 📋 Combina datos 🏁 Sincroniza
⚙️ Modos del nodo Merge
🚦
Append
Agrega todos los items de ambas ramas en una lista combinada. El más común.
🔀
Merge By Index
Une item #1 de rama A con item #1 de rama B, item #2 con #2, etc.
⏳
Wait
Espera a que AMBAS ramas lleguen antes de continuar. Para sincronizar procesos paralelos.

Loop Over Items

Procesa cada elemento de una lista por separado. Cuando tienes 10, 100 o 1000 registros y necesitas ejecutar una acción por cada uno.

🔁
Loop Over Items · Iteración
Repite la acción por cada elemento
Imagina que tienes una lista de 50 clientes y necesitas enviarle un email personalizado a cada uno. Loop Over Items itera sobre cada registro y ejecuta los nodos siguientes una vez por cada elemento. Sin Loop, tendrías que hacerlo manualmente.
🔁 Itera lista 📦 Procesa 1 a 1 ⏱️ Control de ritmo 📋 Batch size
⚙️ Cómo funciona el Loop
// Llegan 3 clientes del nodo anterior [ { "nombre": "Laura", "email": "laura@x.com" }, { "nombre": "Carlos", "email": "carlos@x.com" }, { "nombre": "Ana", "email": "ana@x.com" } ] // Loop Over Items los procesa así: Vuelta 1 → procesa Laura → envía email a laura@x.com Vuelta 2 → procesa Carlos → envía email a carlos@x.com Vuelta 3 → procesa Ana → envía email a ana@x.com // = 3 emails enviados, 1 por 1
🏢 Casos reales
📧
Email masivo personalizado: 500 clientes, 1 email único por persona con su nombre y datos
📊
Registrar en Sheets: lista de pedidos del día → cada uno en su propia fila
🤖
Procesar con IA: 20 reseñas de clientes → analizar sentimiento de cada una
🔄
Actualizar CRM: lista de contactos importados → crear registro por cada uno
⚠️ Consideraciones importantes
⏱️
Velocidad: 1000 items × 1 seg/item = ~17 min. Considera el tiempo de ejecución
📦
Batch size: puedes configurar cuántos items procesar por lote (ej: 10 a la vez)
🚦
Rate limits: si llamas una API en el loop, respeta sus límites de peticiones por minuto
💡
Sin loop a veces: algunos nodos (Gmail, Sheets) ya procesan múltiples items solos
