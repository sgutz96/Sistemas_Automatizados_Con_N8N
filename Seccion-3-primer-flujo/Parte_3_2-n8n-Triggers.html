Los Triggers en n8n

El trigger es la decisión más importante de cualquier workflow. Define cuándo, cómo y por qué se activa tu automatización.

🎯 La pregunta central de todo workflow

"¿Qué hace que esto se ejecute?"

Sin un trigger bien elegido, el workflow más sofisticado no sirve de nada. El trigger no es solo técnica — es estrategia. Elegir el equivocado significa automatizar en el momento incorrecto, con los datos incorrectos.

🧠 Cómo funciona un trigger en n8n

Un trigger es el primer nodo de todo workflow. Escucha, espera o detecta un evento y cuando ocurre, activa el flujo y pasa los datos al siguiente nodo.

// Ciclo de vida de un trigger 1. Workflow activado → trigger empieza a escuchar 2. Evento ocurre → trigger captura los datos 3. Datos pasan al siguiente nodo como JSON 4. Resto del flujo se ejecuta con esos datos

Trigger 1 de 5

Webhook Trigger

El trigger más potente y más usado en automatización real. Activa el workflow al instante cuando llega una petición HTTP.

🌐
Webhook Trigger · Tiempo real
Escucha peticiones HTTP en una URL
n8n genera una URL única. Cuando alguien hace un POST, GET o cualquier método HTTP a esa URL, el workflow se dispara inmediatamente con los datos recibidos. Sin espera, sin polling, sin demora.
⚡ Tiempo real 🔗 URL única 📦 Recibe JSON 🔒 Soporta auth 🌍 Cualquier origen
⚙️ Cómo se configura
// Configuración en n8n Nodo: Webhook Método: POST (el más común) Path: /mi-formulario Auth: None / Basic / Header // URL generada por n8n https://tu-n8n.com/webhook/mi-formulario // Datos que llegan al workflow { "body": { ...datos del POST }, "headers": { ...cabeceras HTTP }, "query": { ...parámetros URL } }
📌 Cuándo usarlo
✅
Formularios web que envían datos al ser completados
✅
Integraciones con apps externas vía su sistema de webhooks (Stripe, Shopify, Typeform, etc.)
✅
Eventos en tiempo real donde la velocidad de respuesta importa
✅
Conectar cualquier sistema que pueda hacer una petición HTTP
❌
No usar cuando el sistema externo no soporta enviar webhooks
🏢 Ejemplos reales en la industria
E-commerce
🛍️ Nuevo pedido en Shopify
Shopify envía webhook al completarse una compra → n8n procesa → notifica al equipo de logística + registra en Sheets
Shopify → Webhook → Slack + Sheets
Marketing / Captación
📋 Formulario de Typeform
Prospecto llena formulario → Typeform dispara webhook → n8n crea contacto en CRM + envía email de bienvenida automático
Typeform → Webhook → CRM + Email
Fintech / Pagos
💳 Pago procesado en Stripe
Cliente paga → Stripe envía evento webhook → n8n valida pago + activa acceso al producto + envía factura
Stripe → Webhook → Email + DB
SaaS / Producto
🚨 Alerta de error en producción
Sistema detecta error → envía webhook → n8n crea ticket en Jira + notifica al dev de guardia en Slack
App → Webhook → Jira + Slack
Trigger 2 de 5

Schedule (Cron) Trigger

Automatización basada en tiempo. Se ejecuta en el horario exacto que definas, sin que nadie tenga que hacer nada.

⏰
Schedule Trigger · Basado en tiempo
Se ejecuta en el horario que definas
No necesita un evento externo. n8n tiene un reloj interno que activa el workflow según la programación configurada: cada hora, cada día a las 9am, los lunes a las 8am, el primer día del mes, etc.
⏱️ Sin evento externo 📅 Horario flexible 🔁 Repetición exacta 🌍 Zona horaria
⚙️ Configuración y expresiones Cron
// Ejemplos de configuración // Cada día a las 9:00am 0 9 * * * // Cada lunes a las 8:30am 30 8 * * 1 // Cada hora 0 * * * * // Cada 15 minutos */15 * * * * // Primer día del mes a medianoche 0 0 1 * * // Lunes a Viernes a las 6pm 0 18 * * 1-5
📌 Cuándo usarlo
✅
Reportes periódicos — resumen Seccionl, informe diario de métricas
✅
Recordatorios automáticos — seguimiento a clientes, tareas pendientes
✅
Limpieza de datos — archivar registros antiguos, actualizar bases de datos
✅
Sincronización nocturna — mover datos entre sistemas sin carga de tráfico
❌
No usar cuando necesitas reacción inmediata a un evento
🏢 Ejemplos reales en la industria
Agencias / Consultoría
📊 Reporte Seccionl de métricas
Cada lunes 8am → n8n extrae datos de Google Analytics + Ads → genera resumen → envía por email al cliente automáticamente
Lunes 8am → Analytics → Email cliente
Ventas / CRM
🔔 Seguimiento a leads fríos
Cada día 10am → revisa CRM → filtra leads sin contacto en 7 días → envía alerta al vendedor asignado con la lista
Cada día 10am → CRM → Slack vendedor
Operaciones / Logística
🚚 Actualización de inventario
Cada noche a medianoche → consulta ERP → actualiza stock en tienda online → notifica si hay productos bajo mínimo
Cada noche → ERP → Shopify + Alerta
Recursos Humanos
🎂 Recordatorio de cumpleaños
Cada mañana → revisa HR system → detecta cumpleaños del día → envía felicitación personalizada al colaborador + alerta a su manager
Cada día 9am → HR → Email + Slack
Trigger 3 de 5

Manual Trigger

El más simple de todos. Lo ejecutas tú, cuando quieras, desde el panel de n8n. Esencial para pruebas y procesos on-demand.

▶️
Manual Trigger · On-demand
Tú decides cuándo ejecutar el workflow
No hay evento externo ni horario. Simplemente presionas el botón "Execute Workflow" en la interfaz de n8n y el flujo corre. Ideal para probar, para procesos que se ejecutan rara vez o para equipos no técnicos que necesitan automatizar a demanda.
👆 Control total 🧪 Testing 🔧 Sin config 👥 Equipos no técnicos
⚙️ Cómo funciona
// No requiere configuración Nodo: Manual Trigger Config: Ninguna // Para activarlo: → Abre el workflow en n8n → Clic en "Execute Workflow" → El flujo corre inmediatamente // Datos que pasa al siguiente nodo { "manualTriggerData": {} } // (vacío — no trae datos externos)
📌 Cuándo usarlo
✅
Desarrollo y pruebas — es el trigger por defecto cuando estás construyendo
✅
Procesos infrecuentes — migraciones de datos, cargas masivas puntuales
✅
Workflows internos — que un humano debe revisar antes de ejecutar
✅
Demos y presentaciones — para mostrar el workflow en acción sin esperar eventos
❌
No usar en producción para procesos que deberían correr solos sin intervención
🏢 Ejemplos reales en la industria
Operaciones / Data
📥 Migración de datos puntual
Una vez al mes el equipo ejecuta manualmente el workflow que mueve datos históricos del ERP a BigQuery para análisis
Manual → ERP → BigQuery
Marketing
📤 Envío de campaña especial
El equipo revisa el contenido, aprueba internamente, y cuando está listo ejecuta el workflow que envía la campaña a la lista segmentada
Manual → Segmento → Email masivo
Soporte / CS
🔁 Reset masivo de contraseñas
Ante incidente de seguridad, el admin ejecuta el workflow que invalida sesiones y envía emails de reset a todos los usuarios afectados
Manual → DB usuarios → Email reset
Finanzas
🧾 Generación de facturas del mes
El último día de cada mes, el equipo de finanzas ejecuta el workflow que genera y envía todas las facturas del período a los clientes
Manual → CRM → Facturas PDF
Trigger 4 de 5

Email Trigger

El workflow se activa cuando llega un email a una bandeja. Convierte el email en el punto de entrada de tus automatizaciones.

📧
Email Trigger (IMAP) · Basado en eventos de correo
Se activa cuando llega un email nuevo
n8n monitorea una bandeja de correo vía IMAP. Cuando llega un email nuevo (o que cumpla ciertos filtros), el workflow se dispara con todo el contenido del email: asunto, remitente, cuerpo, adjuntos y más.
📬 Bandeja IMAP 🔍 Filtros por asunto 📎 Adjuntos ✉️ Gmail / Outlook
⚙️ Datos disponibles del email
// Lo que llega al siguiente nodo { "from": "cliente@email.com", "to": "soporte@empresa.com", "subject": "Problema con mi pedido #1234", "text": "Hola, necesito ayuda con...", "html": "<p>Hola...</p>", "date": "2025-01-15T10:30:00Z", "attachments": [ ... ] }
📌 Cuándo usarlo
✅
Soporte al cliente — cada email a soporte@ crea un ticket automático
✅
Procesamiento de pedidos — emails de proveedores disparan actualizaciones
✅
Clasificación automática — categorizar y enrutar emails por asunto o remitente
✅
Alertas desde sistemas legados — sistemas viejos que solo saben mandar emails
❌
No usar si el volumen de email es muy alto — considera filtros bien definidos
🏢 Ejemplos reales en la industria
Soporte / Customer Success
🎫 Creación automática de tickets
Llega email a soporte@empresa.com → n8n extrae asunto + remitente → crea ticket en Zendesk/Freshdesk → responde con acuse de recibo al cliente
Email → Zendesk + Auto-reply
Importación / Compras
📦 Confirmación de envío de proveedor
Proveedor envía email de confirmación → n8n detecta por asunto → extrae número de guía → actualiza ERP + notifica al equipo de almacén
Email proveedor → ERP + Slack almacén
Contabilidad
🧾 Procesamiento de facturas recibidas
Llega factura por email como PDF → n8n descarga adjunto → extrae datos con IA → registra en sistema contable para aprobación
Email con PDF → IA → Sistema contable
RRHH / Reclutamiento
👤 CVs recibidos en bandeja
Candidato envía CV a empleos@empresa.com → n8n captura el email + adjunto → crea perfil en ATS + asigna al reclutador correcto
Email + CV → ATS + Reclutador
Trigger 5 de 5

Polling Trigger

Consulta periódicamente una fuente de datos y actúa solo cuando encuentra algo nuevo. El puente hacia apps que no tienen webhooks.

🔄
Polling Trigger · Consulta activa periódica
Pregunta regularmente si hay algo nuevo
A diferencia del webhook (que espera a que alguien llame), el polling es proactivo: n8n pregunta a la fuente cada X minutos "¿hay datos nuevos?". Si los hay, ejecuta el workflow. Si no, espera. Funciona con apps que no envían webhooks.
🔍 Detecta cambios ⏱️ Intervalo config. 📡 Sin webhook externo 🔗 Google Sheets, RSS…
⚙️ Cómo funciona el polling
// Ciclo de polling Cada: 5 minutos (configurable) 1. n8n consulta la fuente 2. Compara con última ejecución 3a. Hay nuevos datos → ejecuta flujo 3b. Sin cambios → espera // Nodos con polling incorporado → Google Sheets Trigger → RSS Feed Trigger → Airtable Trigger → GitHub Trigger → Trello Trigger
📌 Cuándo usarlo
✅
Google Sheets como base de datos — actuar cuando alguien agrega una fila
✅
Monitorear RSS / noticias — detectar artículos nuevos y procesarlos
✅
Cambios en Airtable / Notion — reaccionar a actualizaciones de registros
✅
Apps sin API de webhooks — cuando no hay otra opción técnica
❌
No usar para tiempo real crítico — siempre hay retraso del intervalo
🏢 Ejemplos reales en la industria
Ventas / Operaciones
📊 Nuevo registro en Google Sheets
El equipo de ventas llena un Google Sheet con nuevos clientes → n8n detecta fila nueva cada 5 min → crea contacto en CRM automáticamente
Sheets nuevo registro → CRM
Contenido / Media
📰 Monitor de noticias RSS
n8n monitorea RSS de TechCrunch cada 30 min → detecta artículo nuevo → extrae título + link → publica resumen en canal de Slack del equipo
RSS feed → Slack equipo
Desarrollo / DevOps
🐛 Nuevo issue en GitHub
n8n monitorea repositorio → detecta issue nuevo con label "bug" → crea tarea en Jira + notifica al tech lead + asigna según área
GitHub issue → Jira + Slack TL
E-commerce / Inventario
🔴 Producto sin stock en Airtable
Base de datos en Airtable actualiza stock → n8n detecta cambio cuando stock llega a 0 → alerta automática al equipo de compras
Airtable cambio → Email compras

Sección 8

¿Cuál Trigger Usar?

El árbol de decisión para elegir el trigger correcto en cualquier situación. Una pregunta a la vez.

🔍 Árbol de decisión — elige tu trigger
Pregunta 1
¿Necesitas que el workflow reaccione a algo que ocurre ahora mismo?
SÍ → ¿El sistema externo puede enviar una petición HTTP?
SÍ → 🌐 Webhook
NO → 🔄 Polling o 📧 Email
NO → Ve a la Pregunta 2
Pregunta 2
¿Quieres que se ejecute automáticamente en un horario fijo?
SÍ → ⏰ Schedule (Cron)
NO → Ve a la Pregunta 3
Pregunta 3
¿Lo ejecutas tú manualmente cuando lo necesitas?
SÍ → ▶️ Manual Trigger
ESPECIAL → Si el evento es un email entrante: 📧 Email Trigger
✅ Resumen para llevarte
  • 🌐
    Webhook — cuando otro sistema te notifica. La opción por defecto para integraciones profesionales.
  • ⏰
    Schedule — cuando el tiempo es el detonador. Reportes, recordatorios, sincronizaciones nocturnas.
  • ▶️
    Manual — cuando tú decides. Imprescindible en desarrollo; limitado en producción.
  • 📧
    Email — cuando el email es la fuente de datos. Muy útil para soporte y sistemas legados.
  • 🔄
    Polling — cuando no hay webhook disponible. El puente hacia apps que no tienen API de eventos.
