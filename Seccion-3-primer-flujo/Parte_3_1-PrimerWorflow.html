Sección 2

Conceptos Clave

Los tres pilares de cualquier automatización en n8n. Entiéndelos bien y el resto es construcción.

🔸 Workflow

Flujo de automatización

Un workflow es el conjunto de nodos conectados que define qué hace tu automatización, en qué orden y con qué datos. Es el mapa completo del proceso automatizado.

// Un workflow tiene siempre esta estructura trigger → nodo_proceso → acción_final
🔸 Trigger — evento de inicio

Dispara el flujo

El trigger es el punto de partida. Sin trigger no hay automatización. Escucha eventos y activa el workflow cuando ocurren.

🌐 Webhook ⏰ Cron 📡 Evento externo ▶️ Manual
🔸 Acción — resultado del flujo

Ejecuta algo real

Las acciones son los nodos que hacen cosas: enviar datos, crear registros, notificar a personas o transformar información.

📨 Enviar datos 📝 Crear registros 🔔 Notificar 🔄 Transformar
⚙️ Nodos de procesamiento — el puente
🔧

Set

Organiza, renombra o define campos en los datos. Es el nodo más usado en workflows básicos.

organizar datos
⚡

Function

Ejecuta código JavaScript personalizado para transformaciones que Set no puede hacer.

lógica avanzada
🔀

Lógica condicional. El flujo toma caminos distintos según los datos que recibe.

① Entrada

Webhook recibe datos

El webhook queda escuchando en una URL. Cuando llega una petición, el workflow se activa automáticamente con los datos recibidos.

POST /webhook/mi-flujo { "nombre": "Laura", "email": "laura@..." }
② Procesamiento

Nodo SET organiza

El nodo Set toma los datos crudos del webhook y los reorganiza, formatea o enriquece para que el siguiente paso los entienda correctamente.

mensaje = "Nuevo lead: " + nombre destino = email timestamp = Date.now()

Envío de notificación

El nodo de acción recibe los datos procesados y ejecuta la tarea real: enviar un email, un mensaje de Slack, Telegram, o lo que necesites.

Sección 5

Paso a Paso

Los 9 pasos para construir y ejecutar tu primer workflow. Síguelos en orden, uno a la vez.

📌 Construcción del workflow
  • 1

    Crear un nuevo workflow en n8n

    Entra a tu instancia de n8n, haz clic en "New Workflow" y dale un nombre descriptivo. Por ejemplo: Notificación - Formulario Lead. Nombrarlo bien desde el inicio te ahorra confusión después.

    UI → New Workflow → Nombrar
  • 2

    Agregar un nodo Webhook

    Haz clic en el botón "+" y busca el nodo Webhook. Este será tu trigger: el punto de entrada de los datos al workflow.

    + → Buscar "Webhook" → Agregar
  • 3

    Configurar el trigger

    Elige el método HTTP (POST en la mayoría de casos). n8n te dará una URL única para tu webhook. Cópiala — la usarás para enviar datos de prueba.

    Método: POST → Copiar URL del webhook
  • 4

    Añadir nodo de procesamiento (Set)

    Agrega el nodo Set después del webhook. Aquí definirás los campos que quieres usar en los siguientes pasos: nombre del mensaje, destinatario, formato, etc.

    + → Set → Definir campos de salida
  • 5

    Agregar nodo de acción

    Conecta el nodo de tu canal elegido: Gmail, Slack, Telegram u otro. Configura el destinatario y el contenido del mensaje usando las variables del paso anterior.

    + → Gmail / Slack / Telegram → Configurar
  • 6

    Conectar todos los nodos

    Arrastra desde el punto de salida de cada nodo al punto de entrada del siguiente. El flujo debe ser lineal: Webhook → Set → Acción. Verifica que todas las conexiones estén activas.

    Arrastrar conexiones → Verificar flujo completo
  • 7

    Ejecutar el flujo

    Activa el workflow con el botón Execute Workflow. En modo prueba puedes activar primero el webhook y enviar datos manualmente para ver qué pasa.

    Execute Workflow → Webhook listening...
  • 8

    Probar con datos reales

    Usa Postman, cURL o un formulario para enviar un POST a la URL de tu webhook. n8n mostrará los datos en tiempo real en cada nodo.

    curl -X POST TU_WEBHOOK_URL \ -H "Content-Type: application/json" \ -d '{"nombre":"Laura","email":"laura@email.com"}'
  • 9

    Validar resultados

    Confirma que la notificación llegó correctamente. Revisa cada nodo en n8n para ver los datos de entrada y salida. Si algo falla, n8n te muestra exactamente dónde y por qué.

    Revisar logs → Verificar notificación recibida

Ejemplo Real

Así se ven los datos en cada etapa del workflow. Entrada, procesamiento y salida con datos concretos.

📧 Caso completo: Lead desde formulario → Notificación
🔹 Input — webhook recibe
{ "nombre": "Laura", "email": "laura@email.com", "empresa": "Startup ABC", "fuente": "formulario-web" }
→
🔹 Output — acción envía
{ "mensaje": "Nuevo lead recibido", "para": "ventas@empresa.com", "asunto": "Lead: Laura - Startup ABC", "timestamp": "2025-01-15T10:30:00Z" }
⚙️ Transformación en el nodo Set

Así defines los campos de salida en el nodo Set usando los datos del webhook:

// Nodo SET — mapeo de campos mensaje = "Nuevo lead recibido: " + {{$json.nombre}} asunto = "Lead: " + {{$json.nombre}} + " - " + {{$json.empresa}} para = ventas@empresa.com fuente = {{$json.fuente}} timestamp = {{$now}}
✅ Notificación por Email
// Gmail / SMTP Para: ventas@empresa.com Asunto: {{asunto}} Cuerpo: Nombre: {{$json.nombre}} Email: {{$json.email}} Empresa: {{$json.empresa}}
💬 Notificación por Slack
// Slack message Canal: #leads Mensaje: 🔔 Nuevo lead: → Nombre: {{$json.nombre}} → Email: {{$json.email}} → Empresa: {{$json.empresa}}

✅ Hazlo así

  • ✓Nombra los nodos con su función real
  • ✓Prueba cada nodo individualmente
  • ✓Valida los datos antes de cada acción
  • ✓Usa datos claros y descriptivos

Sección 7

Errores Comunes

Los problemas más frecuentes al construir el primer workflow. Conocerlos de antemano te ahorra horas de depuración.

🚫 Errores que debes evitar
  • ✗
    No conectar correctamente los nodos
    Un nodo desconectado no ejecuta. En n8n cada nodo debe tener una línea de conexión visible desde el nodo anterior. Verifica siempre el grafo completo antes de ejecutar.
  • ✗
    No probar el trigger antes de continuar
    Si el webhook no recibe datos, el resto del flujo no importa. Activa el modo "Listen for Test Event" y envía un POST antes de configurar el Set o la acción.
  • ✗
    Ignorar el formato de los datos
    n8n trabaja con JSON. Si envías datos en formato incorrecto, el nodo Set no encontrará los campos y el flujo fallará silenciosamente. Revisa la estructura del payload.
  • ✗
    Automatizar sin entender el flujo primero
    Antes de abrir n8n, dibuja el flujo en papel. Trigger → qué datos llegan → qué necesito hacer con ellos → qué acción ejecuto. Sin este mapa mental, te perderás entre nodos.
  • ✗
    Activar el workflow sin validar resultados
    Un workflow activo que falla en silencio es peor que uno inactivo. Siempre confirma que la notificación llegó antes de declarar el workflow como listo.
✅ Buenas prácticas para workflows reales
  • ✓
    Mantener los flujos simples al inicio
    Un workflow de 3 nodos que funciona vale más que uno de 15 que nadie entiende. Agrega complejidad solo cuando lo simple ya está probado.
  • ✓
    Probar cada nodo individualmente
    n8n te permite ejecutar nodos por separado. Úsalo: prueba el webhook solo, luego el Set, luego la acción. Así identificas exactamente dónde está el problema.
  • ✓
    Usar datos reales desde el primer test
    Los datos ficticios esconden problemas que aparecen en producción. Usa emails reales, nombres reales, formatos reales desde la primera prueba.
  • ✓
    Nombrar los nodos correctamente
    "Webhook - Recibe Lead", "Set - Formatea Mensaje", "Gmail - Notifica Ventas". En 3 Seccions cuando revises el workflow, sabrás exactamente qué hace cada nodo.

Sección 8

Entregable y Cierre

Lo que debes tener funcionando al finalizar esta clase. Este workflow es la base sobre la que construirás automatizaciones más complejas.

📦 Entregable de la Seccion 3

Un workflow funcional en n8n

⚡

Se activa automáticamente o manualmente

El workflow debe poder ejecutarse con un trigger real (webhook) o con el botón manual. Ambos deben funcionar correctamente.

🔧

Procesa datos correctamente

El nodo Set debe transformar los datos de entrada en el formato esperado por la acción. Sin datos rotos, sin campos vacíos.

📤

Ejecuta una acción real (notificación o registro)

La notificación debe llegar a destino: un email, mensaje de Slack, Telegram u otro canal. Verificado, no asumido.

🏷️

Nodos correctamente nombrados

Cada nodo con un nombre que describa su función. Nada de "Set 1", "Webhook 2". Nombres claros para flujos mantenibles.

✅

Validado con datos reales de prueba

Al menos una ejecución exitosa con datos reales. El resultado debe estar visible en el historial de ejecuciones de n8n.
