Sistema de Leads Automatizados

El primer sistema real de negocio. Captura, valida, almacena y notifica cada lead de forma automática, sin intervención humana.

🎯 Objetivo de la clase

Crear un flujo automatizado que recibe datos, los procesa y los almacena para seguimiento

Pasamos de workflows de práctica a un sistema funcional de negocio. Cada vez que alguien envíe sus datos — desde un formulario, una app o una API — el sistema los captura, valida, organiza y guarda sin que nadie tenga que hacer nada.

Sección 2

Conceptos Clave

Los tres pilares conceptuales del sistema. Entenderlos define cómo diseñas el flujo y qué decisiones tomas en cada etapa.

🔸 Lead

Persona interesada con datos

Un lead es una persona que dejó sus datos porque tiene interés en un producto o servicio. No es solo un contacto — es una oportunidad de negocio que necesita seguimiento. Cada lead tiene un valor y merece ser tratado correctamente desde el primer segundo.

👤 Persona real 💰 Oportunidad 📋 Con datos
🔸 Captura de datos

Cómo llegan los datos al sistema

Los datos pueden llegar desde múltiples fuentes. El sistema debe ser agnóstico al origen — no importa si viene de un formulario web, una app móvil o una integración directa. El webhook es el punto de entrada universal que los recibe todos.

📋
Formularios web (Typeform, Google Forms)
🌐
Webhooks de apps y plataformas
🔗
APIs y sistemas externos directos
🔸 Persistencia

Guardar para uso futuro

Persistir significa guardar los datos en un sistema externo que sobrevive más allá del workflow. n8n procesa pero no almacena — el almacenamiento es siempre externo: Sheets, Airtable, una DB. Sin persistencia, el lead existe solo durante la ejecución y se pierde.

📊
Google Sheets — equipo no técnico
📋
Airtable — CRM visual y flexible

Paso 1 de 5

Captura — Webhook Trigger

El punto de entrada del sistema. Configura el webhook, obtén la URL y prueba que los datos llegan correctamente antes de continuar.

🌐 Configuración del nodo Webhook
// Configuración en n8n Nodo: Webhook HTTP Method: POST Path: /captura-lead Auth: None (o Header Auth para producción) Respond: Using 'Respond to Webhook' Node // URL generada por n8n (ejemplo) https://tu-n8n.com/webhook/captura-lead // En modo Test (para desarrollo) https://tu-n8n.com/webhook-test/captura-lead
🧪 Enviar datos de prueba con cURL
# Prueba básica — lead completo curl -X POST \ 'https://tu-n8n.com/webhook-test/captura-lead' \ -H 'Content-Type: application/json' \ -d '{ "nombre": "Juan Pérez", "email": "juan@email.com", "telefono": "3001234567", "interes": "Servicio X", "fuente": "formulario-web" }' # Prueba con datos faltantes (para probar validación) curl -X POST \ 'https://tu-n8n.com/webhook-test/captura-lead' \ -H 'Content-Type: application/json' \ -d '{ "nombre": "Laura", "email": "" }'
📦 Datos que llegan al primer nodo
// n8n expone estos datos en $json { "nombre": "Juan Pérez", "email": "juan@email.com", "telefono": "3001234567", "interes": "Servicio X", "fuente": "formulario-web" } // Acceder en nodos siguientes: {{$json.nombre}} → "Juan Pérez" {{$json.email}} → "juan@email.com" {{$json.telefono}} → "3001234567"
💡
Activa "Listen for Test Event" primero. En n8n haz clic en el webhook y activa el modo escucha antes de enviar el cURL. Verás los datos en tiempo real en el panel de n8n y podrás confirmar que todo llega bien.
⚠️
Modo test vs producción: la URL con /webhook-test/ solo funciona cuando el workflow está abierto en el editor. La URL con /webhook/ funciona 24/7 cuando el workflow está activado.
Paso 2 de 5

Validación de Datos

Ningún lead inválido llega al almacenamiento. La validación protege la calidad de tu base de datos y responde con errores claros al sistema que envió los datos.

🛡️ Nodo IF — validación de campos obligatorios
// Condición del nodo IF // Usando modo AND: TODAS deben cumplirse Condición 1: campo: {{$json.nombre}} operador: no está vacío Condición 2: campo: {{$json.email}} operador: no está vacío Condición 3: campo: {{$json.email}} operador: contiene valor: "@" // ───────────────────────────────── // Rama TRUE: datos válidos → continuar // Rama FALSE: datos inválidos → responder error
❌ Rama FALSE — responder con error 400
// Nodo: Respond to Webhook Status Code: 400 Body: { "success": false, "error": "{{$json.nombre ? '' : 'Nombre requerido. '}}" "{{$json.email ? '' : 'Email requerido.'}}", "code": "VALIDATION_ERROR", "recibido": { "nombre": "{{$json.nombre}}", "email": "{{$json.email}}" } } // El flujo se detiene aquí. // El formulario muestra el error al usuario.
✅ Validaciones adicionales recomendadas
  • ✓
    Email con dominio — verificar que contiene "." después del "@"
    email contiene "@" AND email contiene "."
  • ✓
    No es email de prueba — descartar leads fake
    email no contiene "test" AND email no contiene "example.com"
  • ✓
    Teléfono con longitud mínima — si viene, debe tener al menos 7 dígitos
    telefono.length >= 7
  • ✓
    Nombre mínimo 2 caracteres — evitar caracteres sueltos
    nombre.length >= 2
🔬 Alternativa avanzada: validación con Function
// Para validaciones más complejas, usa Function const data = $input.first().json; const errores = []; if (!data.nombre || data.nombre.trim().length < 2) errores.push("Nombre requerido (mínimo 2 caracteres)"); if (!data.email || !data.email.includes('@')) errores.push("Email inválido"); if (data.telefono && data.telefono.replace(/\D/g,'').length < 7) errores.push("Teléfono debe tener al menos 7 dígitos"); return [{ json: { ...data, valido: errores.length === 0, errores: errores, errores_texto: errores.join(', ') } }]; // Luego IF: valido === true → continuar, false → error
Paso 3 de 5

Procesamiento y Limpieza

Los datos llegan crudos. El nodo Set los transforma en datos limpios, enriquecidos y listos para almacenar y usar.

🔧 Nodo Set — formatear y enriquecer el lead
// ── LIMPIEZA ────────────────────────────────────── nombre → {{$json.nombre.trim()}} email → {{$json.email.toLowerCase().trim()}} telefono → {{($json.telefono ?? '').replace(/\s/g, '')}} interes → {{$json.interes ?? 'No especificado'}} // ── ENRIQUECIMIENTO ─────────────────────────────── fuente → {{$json.fuente ?? 'desconocida'}} fecha → {{$now.toFormat('dd/MM/yyyy HH:mm')}} estado → "nuevo" asignado_a → "Sin asignar" notas → "" // ── SCORE BÁSICO ────────────────────────────────── score → {{ ($json.telefono ? 30 : 0) + ($json.interes ? 40 : 0) + 30 }} // 30 base + 40 si tiene interés + 30 si tiene tel // Máximo 100 — prioridad para el equipo de ventas
📋 Antes vs después del Set
Datos crudos del webhook
"nombre": " JUAN pérez " "email": "JUAN@Email.COM" "telefono": "300 123 4567" "interes": undefined
→
Datos limpios del Set
"nombre": "Juan pérez" "email": "juan@email.com" "telefono": "3001234567" "interes": "No especificado" "estado": "nuevo" "score": 60 "fecha": "15/01/2025 10:30"
🎯 Clasificar por score — Switch opcional
// Después del Set, Switch por score score >= 80: → prioridad = "alta" → asignar_vendedor() → alerta_slack_urgente() score 50-79: → prioridad = "media" → alerta_slack_normal() score < 50: → prioridad = "baja" → solo_registrar() // Todos pasan al almacenamiento // pero con diferentes campos de prioridad
💡
Activa "Keep Only Set" en el nodo Set. Esto hace que solo pasen las variables que tú defines, eliminando el JSON original. El Sheets recibirá exactamente los campos que quieres en el orden correcto, sin basura adicional.
Paso 4 de 5

Almacenamiento — Google Sheets

El lead limpio y procesado llega aquí para quedarse. La configuración correcta del nodo Sheets garantiza que cada campo cae en la columna exacta.

📊 Configuración del nodo Google Sheets
// Nodo: Google Sheets Operation: Append Row Document: "Sistema de Leads 2025" ← nombre de tu hoja Sheet: "Leads" ← pestaña Data Mode: "Auto-map columns" // Mapeo de campos (columna = nombre del header en Sheets) Fecha ← {{$json.fecha}} Nombre ← {{$json.nombre}} Email ← {{$json.email}} Teléfono ← {{$json.telefono}} Interés ← {{$json.interes}} Fuente ← {{$json.fuente}} Estado ← {{$json.estado}} Asignado a ← {{$json.asignado_a}} Score ← {{$json.score}} Notas ← {{$json.notas}}
📋 Variante: guardar en Airtable
// Nodo: Airtable Operation: Create Record Base: "appXXXXXXXXXX" ← ID de tu base Table: "Leads" // Campos (mismo mapeo) Name ← {{$json.nombre}} Email ← {{$json.email}} Phone ← {{$json.telefono}} Interest ← {{$json.interes}} Source ← {{$json.fuente}} Status ← "New" Score ← {{$json.score}} // Airtable retorna el ID del nuevo registro // → usar en la notificación como referencia
⚠️ Manejo de error en almacenamiento
// Activar "Continue on Error" en el nodo Sheets // Para que el workflow no se detenga si Sheets falla Sheets append → éxito: continuar normal → error: item con { error: "..." } ↓ IF error no vacío: Slack: "⚠️ No se pudo guardar lead: {{email}}" Sheets-backup: guardar en hoja "Errores" ← el lead no se pierde // Alternativa: guardar en 2 lugares al mismo tiempo // Sheets principal + Sheets backup en paralelo

Sección 9

Entregable y Errores Comunes

Lo que debes tener funcionando, los errores que debes evitar y el bonus para llevarte el sistema al siguiente nivel.

✅ Entregable — sistema de leads funcionando
  • ✓
    Webhook activo que recibe datos JSON
    URL configurada, método POST, datos llegan al primer nodo correctamente.
  • ✓
    Validación que rechaza leads inválidos
    Leads sin nombre o email reciben respuesta 400 con mensaje claro. No llegan a Sheets.
  • ✓
    Datos limpios y enriquecidos en el Set
    Email en minúsculas, campos vacíos con fallback, timestamp automático, estado inicial.
  • ✓
    Fila creada correctamente en Google Sheets
    Cada lead válido aparece en la hoja con todos sus campos en la columna correcta.
  • ✓
    Notificación enviada al equipo
    Slack o email con los datos del lead y el score de prioridad.
  • ✓
    Respond to Webhook con 200 OK
    El formulario recibe confirmación. El ciclo HTTP queda cerrado correctamente.
  • ✓
    Probado con cURL o Postman
    Al menos 3 pruebas: lead completo, lead sin email, lead sin nombre. Los tres responden correctamente.
⚠️ Errores comunes al construir este sistema
  • ✗
    No crear los headers en Sheets antes
    El nodo de n8n busca las columnas por nombre. Si la hoja está vacía o los nombres no coinciden exactamente, los datos van a columnas equivocadas o da error.
  • ✗
    Olvidar el nodo Respond to Webhook
    Sin él, el formulario queda esperando respuesta hasta el timeout (30s). El usuario ve una pantalla en blanco o un error genérico.
  • ✗
    No manejar la rama false del IF
    Si el IF de validación no tiene la rama false conectada al Respond con 400, los leads inválidos simplemente desaparecen sin respuesta al origen.
  • ✗
    Confundir URL de test con URL de producción
    /webhook-test/ solo funciona con el editor abierto. Para producción activar el workflow y usar /webhook/.
  • ✗
    No activar "Keep Only Set"
    Sin esta opción, el Set pasa todos los campos del webhook + los nuevos. Sheets recibe columnas extra no esperadas que descuadran el mapeo.
🚀 Bonus nivel pro — extensiones del sistema
🔁
Detección de duplicados: antes de guardar, buscar en Sheets si el email ya existe. Si existe, actualizar en vez de crear fila nueva.
🤖
Clasificación con IA: enviar el campo "interés" a la API de Claude/OpenAI y clasificar automáticamente la categoría del lead.
📅
Asignación automática: IF score alto → asignar al vendedor A, score medio → vendedor B, mediante lógica Round Robin.
⏳
Secuencia de seguimiento: usar Wait para enviar email de seguimiento automático a los 2 días si el lead no fue contactado.
📊
Dashboard en tiempo real: segunda hoja con fórmulas que muestran leads por día, por fuente, por estado y conversión.
📱
WhatsApp al lead: si tiene teléfono, enviar confirmación automática por WhatsApp Business API al instante.
