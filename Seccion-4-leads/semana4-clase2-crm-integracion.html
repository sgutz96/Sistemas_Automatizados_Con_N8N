CRM 1 de 3

HubSpot CRM

El nodo nativo de HubSpot en n8n permite crear contactos, deals, empresas y notas directamente desde el workflow.

🟠
HubSpot · Nodo nativo n8n
Contactos, Deals y Companies en un nodo
El nodo HubSpot de n8n tiene acceso completo al CRM: crear y actualizar contactos, abrir deals en el pipeline, asociar empresas y agregar notas. La autenticación es con OAuth2 o Private App Token.
👤 Create Contact💰 Create Deal 🏢 Create Company📝 Add Note🔍 Search Contact
⚙️ Crear contacto en HubSpot
// Nodo: HubSpot → Create Contact firstname: {{$json.nombre.split(' ')[0]}} lastname: {{$json.nombre.split(' ').slice(1).join(' ')}} email: {{$json.email}} phone: {{$json.telefono}} hs_lead_status: "NEW" lifecyclestage: "lead" // Retorna el ID → usar para el deal
⚙️ Crear deal asociado
// Nodo: HubSpot → Create Deal dealname: "{{$json.nombre}} — {{$json.interes}}" pipeline: "default" dealstage: "{{ $json.score >= 80 ? 'qualifiedtobuy' : 'appointmentscheduled' }}" closedate: {{$now.plus({days:30}).toMillis()}} // Asociar al contacto creado antes: contactId: {{$('HubSpot-Contacto').first().json.id}}
🔑 Autenticación — Private App Token
// En HubSpot: Settings → Integrations → Private Apps → Create a private app → nombre: "n8n Integration" → Scopes: crm.objects.contacts.write + crm.objects.deals.write → Copiar el Access Token // En n8n: Credentials → HubSpot API → pegar token
💡
El ID del contacto es clave. Guarda el id que retorna "Crear Contacto" antes de crear el deal. Sin ese ID no puedes asociarlos y quedan huérfanos en HubSpot.

Pipedrive

CRM 100% orientado a ventas. Personas, deals y organizaciones con un pipeline visual potente. Nodo nativo en n8n.

🟢
Pipedrive · Nodo nativo n8n
Persons, Deals y Organizations desde n8n
Pipedrive separa sus entidades en Persons (contactos), Deals (oportunidades) y Organizations (empresas). El nodo n8n cubre las tres. Primero creas la persona, luego el deal, y los asocias con el ID del person.
👤 Create Person💰 Create Deal 🏢 Create Organization🔍 Search Person
⚙️ Crear persona en Pipedrive
// Nodo: Pipedrive → Create Person name: {{$json.nombre}} email: {{$json.email}} phone: {{$json.telefono}} // Retorna: { id: 12345, name: "Juan" } // → personId para el deal
⚙️ Crear deal en Pipedrive
// Nodo: Pipedrive → Create Deal title: "{{$json.nombre}} — {{$json.interes}}" person_id: {{$('Pipedrive-Persona').first().json.id}} pipeline_id: 1 stage_id: {{ $json.score >= 80 ? 2 : $json.score >= 50 ? 1 : 3 }} currency: "COP"

// En Pipedrive: Perfil → Personal preferences → API // → Copiar el Personal API Token // En n8n: Credentials → Pipedrive API → pegar token

Sección 6

Lógica Condicional

El mismo lead, caminos distintos. Según el score y el perfil, el workflow enruta automáticamente: etapa del pipeline, vendedor asignado y acciones paralelas.

🔀 Switch por score — tres caminos distintos
// SWITCH por score del lead score >= 80 → "Lead calificado" ├─ CRM: etapa "Calificado" pipeline stage = qualified ├─ Asignar: vendedor senior Round Robin senior ├─ Slack #leads-urgentes: "🔴 Contactar HOY — Score: {{score}}" └─ Gmail cliente: "Te llamamos hoy" score 50-79 → "Lead interesante" ├─ CRM: etapa "Nuevo" pipeline stage = new ├─ Asignar: vendedor junior Round Robin general ├─ Slack #leads: "🟡 Nuevo lead — seguimiento esta semana" └─ Gmail cliente: "Recibimos tu consulta" score < 50 → "Lead frío" ├─ CRM: etapa "Nurturing" ├─ Solo registro, sin alerta urgente └─ Execute Workflow: "Secuencia-Emails-Fríos" → Wait 3 días → email de valor → Wait 7 días → email de oferta
⚙️ Asignación Round Robin
// Function: rotación automática de vendedores const vendedores = [ "ana@empresa.com", "carlos@empresa.com", "lucia@empresa.com" ]; const idx = Date.now() % vendedores.length; return [{ json: { ...$input.first().json, asignado_a: vendedores[idx] }}];
🏢 IF B2B vs B2C
// Dentro de la rama "Calificado" IF empresa no vacío AND empresa.length > 2 → TRUE (B2B): CRM: crear Company + asociar al Contact Deal: monto estimado mayor Slack: incluir empresa en el mensaje → FALSE (B2C): Sin empresa asociada Deal: monto estándar
Sección 7

Deduplicación Automática

El mismo lead no debe entrar dos veces al CRM. Antes de crear, buscamos. Si existe: actualizar. Si no: crear. Cero duplicados.

🔍 El patrón buscar → decidir → actuar
// Paso 1: Buscar por email en el CRM CRM Search: email == "{{$json.email}}" → resultado: array vacío o con registros // Paso 2: IF ¿existe? IF resultados.length > 0 → TRUE (ya existe): CRM Update Contact: actualizar score, interés, fuente Sheets log: "contacto_actualizado" Slack: "♻️ Lead repetido actualizado: {{email}}" → FALSE (no existe): CRM Create Contact → flujo normal de creación Sheets log: "contacto_creado"
⚙️ Búsqueda en HubSpot
// Nodo: HubSpot → Get All Contacts Filter: email EQ {{$json.email}} Limit: 1 // → [] no existe → crear // → [{id,...}] existe → actualizar
⚙️ Búsqueda en Notion
// Nodo: Notion → Get Many Pages Filter: Property: Email Condition: equals Value: {{$json.email}} // IF results.length > 0: // existe → Update Page // no existe → Create Page
💡
Si el score mejoró, actualiza. Un lead que ya existe pero ahora tiene score más alto puede ser el mismo prospecto con mayor intención de compra. No lo descartes — actualiza y notifica al vendedor asignado.
⚠️
La búsqueda agrega ~500ms. Para evitar timeouts del formulario, usa el patrón "Respond to Webhook primero" de la Clase 1 y procesa la deduplicación en segundo plano.

Entregable y Cierre

El sistema completo de captura y gestión conectado a un CRM real. Esto ya es producción.

✅ Entregable
  • ✓
    CRM conectado y autenticado en n8n
    HubSpot, Pipedrive o Notion con credenciales configuradas y conexión probada.
  • ✓
    Deduplicación funcionando
    Mismo email dos veces: primera crea, segunda actualiza. Verificado en el CRM.
  • ✓
    Contacto Y deal creados y asociados
    Cada lead válido genera dos registros vinculados en el CRM.
  • ✓
    Lógica condicional por score activa
    Score ≥80 → Calificado. Score <50 → Nurturing. Probado con 3 perfiles distintos.
  • ✓
    Asignación automática de vendedor
    Campo "asignado a" en el CRM se llena automáticamente con Round Robin.
  • ✓
    Múltiples acciones paralelas en rama calificada
    CRM + Slack + Gmail + Sheets ejecutan simultáneamente para lead de alto score.
  • ✓
    Probado con 5 leads distintos
    Score alto, medio, bajo, duplicado e inválido — todos con el comportamiento esperado.
⚠️ Errores frecuentes
  • ✗
    No compartir la DB de Notion
    Aunque la credencial esté bien, sin el paso de compartir la DB con la integración, n8n no puede acceder.
  • ✗
    Crear deal sin esperar el ID del contacto
    Los nodos de contacto y deal deben ser secuenciales. Si corren en paralelo, el deal no tiene el ID para asociarse.
  • ✗
    IF con resultado vacío de búsqueda
    La búsqueda retorna [] cuando no hay resultados. El IF debe comparar resultados.length, no el objeto directo.
  • ✗
    IDs de pipeline/etapa hardcodeados sin verificar
    Los IDs varían por cuenta en Pipedrive y HubSpot. Cópialos de tu CRM real, no uses los del ejemplo.
🚀 Bonus nivel pro
🤖
Clasificación con IA: enviar el campo "interés" a Claude API y recibir categoría automática del lead para asignación más precisa.
📅
Tarea de seguimiento automática: después del deal, crear tarea en el CRM asignada al vendedor con vencimiento a 24h.
🔄
Sincronización bidireccional: cuando el vendedor cambia el estado en el CRM, un webhook notifica a n8n que actualiza Sheets.
⏳
Alerta de leads sin contacto: Schedule diario → buscar deals sin actividad en 48h → Slack al vendedor asignado.
