Automatizaciones con IA

Los workflows basados en reglas fijas tienen un límite: no entienden contexto, no se adaptan y fallan ante lo inesperado. La IA elimina ese límite. A partir de esta clase, tus sistemas piensan.

🔥 El salto definitivo
Clases 1–7 — Automatización con reglas
"Si tipo = soporte → hacer X"

El sistema solo actúa si el dato coincide exactamente con una regla predefinida. Cualquier variación, lenguaje natural o ambigüedad lo rompe.

Clase 8 — Automatización con IA
"Analiza, entiende y decide"

La IA lee el mensaje completo, entiende la intención, clasifica con contexto y genera una respuesta personalizada. Sin reglas rígidas, sin casos rotos.

Sección 2

Conceptos Clave

Cuatro conceptos que definen cómo funcionan los modelos de lenguaje dentro de un workflow de automatización.

🔸 Modelo de lenguaje (LLM)

Un sistema de IA entrenado para entender y generar texto. Recibe un prompt (instrucción + contexto) y devuelve texto generado. En n8n, es un nodo que hace una llamada a una API.

// Así lo ve n8n internamente // (simplificado) POST https://api.openai.com/v1/chat/completions { "model": "gpt-4o-mini", "messages": [ { "role": "system", "content": "Tu instrucción aquí" }, { "role": "user", "content": "{{$json.mensaje}}" } ] }
🔸 Prompt — la instrucción que controla la IA

El prompt es lo más importante de toda la integración. Un prompt bueno devuelve siempre el formato correcto. Un prompt ambiguo devuelve resultados impredecibles que rompen el workflow.

// Prompt malo ← ambiguo "Analiza este mensaje: {{mensaje}}" // Devuelve: párrafo de análisis, no clasificación // Prompt bueno ← específico y controlado "Clasifica el siguiente mensaje en una de estas categorías exactas: ventas | soporte | facturacion | otro Responde SOLO con la categoría, sin explicación ni puntuación adicional. Mensaje: {{$json.mensaje}}" // Devuelve: "ventas" ← predecible, parseable

🔸 Tokens — cómo se mide y cobra la IA

Los modelos no leen palabras sino tokens: fragmentos de texto de ~4 caracteres. El costo se calcula por tokens de entrada (prompt) y tokens de salida (respuesta).

// Regla práctica de tokens 1 token ≈ 4 caracteres en inglés 1 token ≈ 3 caracteres en español 100 palabras ≈ 130 tokens // Ejemplo de costo real (GPT-4o mini) Prompt de clasificación: ~80 tokens Respuesta esperada: ~5 tokens Total por solicitud: ~85 tokens Costo: 0.15$ / 1M tokens input = $0.0000128 por solicitud // 1000 solicitudes/día = $0.013/día ≈ $0.39/mes

Paso 1 de 3

Escribir Prompts Efectivos

El prompt es el código de la IA. Un prompt bien escrito hace que la IA devuelva siempre exactamente lo que necesitas. Un prompt vago produce respuestas impredecibles que rompen el workflow.

✍️ Las 5 reglas de los prompts para workflows
  • 1
    Especifica el formato de salida exacto
    Si necesitas JSON, dilo. Si necesitas una sola palabra, dilo. "Responde SOLO con un objeto JSON válido sin markdown ni texto adicional" es la instrucción más importante de cualquier prompt para workflows.
  • 2
    Define todas las opciones posibles
    "Clasifica en: ventas | soporte | facturacion | otro" es mejor que "clasifica el mensaje". Con opciones fijas, la IA no puede inventar categorías nuevas que rompan tu Switch.
  • 3
    Da un ejemplo de output esperado
    Few-shot prompting: incluir 1–2 ejemplos de input→output en el prompt mejora dramáticamente la consistencia de las respuestas. La IA imita el patrón.
  • 4
    Instrucciones en el system prompt, datos en el user
    El system prompt define el comportamiento fijo ("Eres un clasificador de mensajes..."). El user message lleva los datos variables ("{{$json.mensaje}}"). Esta separación mejora la precisión.
  • 5
    Maneja el caso "no sé" explícitamente
    Siempre incluye una categoría de fallback ("otro" o "desconocido") para que la IA no se invente una categoría cuando no está segura. Mejor un "otro" predecible que una categoría aleatoria.
✅ Prompt de clasificación — versión producción
// System prompt (fijo, va en el nodo OpenAI) Eres un sistema de clasificación de mensajes para una empresa de software B2B. Analiza el mensaje del usuario y responde ÚNICAMENTE con un objeto JSON con este formato: { "categoria": "ventas|soporte|facturacion|info|otro", "confianza": "alta|media|baja", "razon": "una frase corta explicando la clasificación" } Sin texto adicional, sin markdown, sin explicaciones. Ejemplos: INPUT: "quiero conocer los precios" OUTPUT: {"categoria":"ventas","confianza":"alta","razon":"consulta de pricing"} // User prompt (dinámico, usa datos del workflow) Mensaje del usuario: {{$json.mensaje}} Canal: {{$json.canal || 'web'}} Plan actual: {{$json.plan || 'desconocido'}}
⚙️ Configurar nodo OpenAI en n8n
// Nodo: OpenAI — configuración Resource: Chat Operation: Message a Model Model: gpt-4o-mini Max Tokens: 150 ← limitar output ahorra costo Temperature: 0 ← 0 = más determinista ← 1 = más creativo // Messages: System: [tu system prompt aquí — fijo] User: {{$json.mensaje}} // Alternativa: nodo HTTP Request // Para cualquier otro modelo (Claude, Gemini...) // usando sus APIs directamente
⚠️
Temperature 0 para clasificación, Temperature 0.7+ para generación. Cuando necesitas que la IA clasifique o extraiga datos (respuesta determinista), usa temperature: 0. Cuando necesitas que redacte un email o genere texto creativo, sube a 0.7 para más variedad. Nunca uses temperature alto para clasificación: las respuestas se vuelven impredecibles.
Paso 2 de 3

Clasificación Inteligente con IA

La IA devuelve texto. El workflow necesita datos. Este paso muestra cómo parsear la respuesta de la IA, validarla y usarla para enrutar el flujo con un Switch.

⚙️ Nodo Code — parsear y validar la respuesta de la IA
// Nodo: Code — después del nodo OpenAI const d = $input.first().json; // ── EXTRAER TEXTO DE LA RESPUESTA ──────────────── const textoIA = d.message?.content || d.choices?.[0]?.message?.content || ''; // ── PARSEAR JSON DE LA RESPUESTA ───────────────── let clasificacion; try { // Limpiar posibles backticks de markdown const limpio = textoIA .replace(/```json|```/g, '') .trim(); clasificacion = JSON.parse(limpio); } catch (e) { // Si no es JSON válido, usar fallback clasificacion = { categoria: 'otro', confianza: 'baja', razon: 'parse_error: ' + textoIA.slice(0,50) }; } // ── VALIDAR CATEGORÍA ───────────────────────────── const categoriasValidas = [ 'ventas','soporte','facturacion','info','otro' ]; if (!categoriasValidas.includes(clasificacion.categoria)) { clasificacion.categoria = 'otro'; clasificacion.confianza = 'baja'; } return [{ json: { ...$input.first().json, ← datos originales ia_categoria: clasificacion.categoria, ia_confianza: clasificacion.confianza, ia_razon: clasificacion.razon, ia_raw: textoIA ← para debug }}];
🔢 Switch sobre ia_categoria
// Nodo: Switch Campo: {{$json.ia_categoria}} Mode: Rules // Output 0 Equals "ventas" → Nodo: generar propuesta comercial // Output 1 Equals "soporte" → Nodo: crear ticket + notificar equipo // Output 2 Equals "facturacion" → Nodo: verificar datos y emitir factura // Output 3 Equals "info" → Nodo: respuesta automática FAQ // Fallback → Nodo: escalar a revisión manual
🔀 IF de confianza — segunda capa de validación
// Antes del Switch, verificar la confianza de la IA // Si la confianza es baja, no confiar en la clasificación Value 1: {{$json.ia_confianza}} Operation: Not Equals Value 2: "baja" ✓ True → confianza alta/media → continuar al Switch normalmente ✗ False → confianza baja → enviar a revisión humana: Slack: "⚠️ Clasificación incierta: {{$json.ia_razon}} — revisar" // Esto evita que errores de la IA // enruten solicitudes por la ruta equivocada
🔥
IA + reglas = sistema robusto. Nunca dependas 100% de la IA en producción. El patrón correcto es: IA clasifica → regla valida la confianza → si confianza alta, actuar automáticamente; si baja, escalar a humano. La IA amplifica al equipo, no lo reemplaza completamente.
Paso 3 de 3

Generación de Respuestas Inteligentes

El segundo uso de la IA en el workflow: redactar la respuesta. A diferencia de la clasificación (temperatura 0), aquí queremos creatividad controlada: respuestas personalizadas que suenan humanas.

💬 Prompt de generación — respuesta para cada categoría
// System prompt para rama VENTAS Eres el asistente comercial de [Empresa]. Tu tono es profesional, amigable y conciso. Escribe un email de respuesta personalizado para el siguiente lead. El email debe: - Usar el nombre del cliente - Mencionar específicamente su consulta - Incluir una propuesta de valor breve - Terminar con un CTA claro (llamada/demo) - Máximo 150 palabras - Tono: profesional pero cercano // User prompt — datos del lead Nombre: {{$json.nombre}} Consulta original: {{$json.mensaje}} Plan de interés: {{$json.plan || 'no especificado'}} Empresa: {{$json.empresa || 'no especificada'}}
// System prompt para rama SOPORTE Eres el equipo de soporte de [Empresa]. Tu tono es empático, claro y solucionador. Escribe la confirmación de recepción del ticket. El mensaje debe: - Confirmar que recibiste la solicitud - Mencionar el problema específico - Dar el número de ticket - Indicar el tiempo de respuesta según prioridad - Ofrecer alternativas de contacto urgente - Máximo 100 palabras // User prompt Nombre: {{$json.nombre}} Problema: {{$json.mensaje}} Ticket ID: {{$json.solicitud_id}} Prioridad: {{$json.prioridad}} SLA: {{$json.sla_minutos}} minutos
✅ Registrar la interacción completa en Sheets
// Nodo: Google Sheets — Append al final del flujo // Una fila por cada mensaje procesado A → {{$now.toFormat('dd/MM/yyyy HH:mm')}} B → {{$json.nombre}} C → {{$json.email}} D → {{$json.mensaje.slice(0,100)}} E → {{$json.ia_categoria}} F → {{$json.ia_confianza}} G → {{$json.prioridad}} H → "respuesta_enviada" I → {{$json.respuesta_ia.slice(0,200)}} // Este registro es el historial de interacciones // que el equipo puede revisar y usar para mejorar // los prompts con el tiempo
⚠️ Control de costos — límites y optimización
// Nodo Code — antes de llamar a la IA // Verificar si realmente necesitamos IA const d = $input.first().json; const msg = d.mensaje.toLowerCase(); // Reglas rápidas sin costo de IA const reglasRapidas = { 'precio': 'ventas', 'no funciona': 'soporte', 'factura': 'facturacion' }; for (const [clave, cat] of Object.entries(reglasRapidas)) { if (msg.includes(clave)) { return [{ json: { ...d, ia_categoria: cat, ia_confianza: 'alta', uso_ia: false ← gratis }}]; } } // Si no hay regla → usar IA return [{ json: { ...d, uso_ia: true } }];
Sección 8

Buenas Prácticas y Errores Comunes

Integrar IA en workflows de producción tiene sus particularidades. Estos son los patrones que hacen la diferencia entre un sistema que falla silenciosamente y uno confiable.

✅ Buenas prácticas
  • ✓
    Escribir prompts claros con formato explícito
    "Responde SOLO con JSON válido, sin markdown, sin texto adicional." Esta instrucción es obligatoria en cualquier prompt que alimente un workflow automatizado.
  • ✓
    Controlar siempre el formato de salida
    Define el schema exacto del JSON que esperas. Incluye un ejemplo en el prompt. Usa temperature 0 para clasificación. Así la IA casi nunca se sale del formato.
  • ✓
    Validar y tener fallback para respuestas de IA
    Siempre envuelve el JSON.parse en try/catch. La IA puede devolver texto inesperado el 1–2% de las veces. Sin fallback, ese 2% rompe el workflow en producción.
  • ✓
    Combinar IA + reglas + APIs
    El mejor sistema es híbrido: reglas rápidas gratis para los casos obvios, IA para los ambiguos, y APIs externas para las acciones. No uses IA donde una regla funciona igual.
  • ✓
    Probar múltiples casos incluyendo edge cases
    Prueba con mensajes bien escritos, mensajes con errores de tipeo, mensajes muy cortos ("precio?"), mensajes en otro idioma y mensajes sin sentido. El sistema debe manejar todo.
⚠️ Errores comunes
  • ✗
    Prompts ambiguos sin formato definido
    "Analiza este mensaje y dime qué tipo es" devuelve un párrafo de análisis, no un valor parseable. La IA siempre necesita instrucciones explícitas del formato de salida esperado.
  • ✗
    No controlar la salida ni parsearla
    Usar directamente $json.message.content como valor en el Switch. Si la IA responde "Ventas" en vez de "ventas", la regla no coincide y el Switch falla silenciosamente.
  • ✗
    Depender 100% de la IA sin validación
    La IA tiene una tasa de error del 1–3%. En 1000 solicitudes diarias son 10–30 errores. Sin validación de confianza y fallback, esos errores ejecutan acciones incorrectas en tu sistema.
  • ✗
    Costos innecesarios por prompts largos
    Meter todo el historial de conversación en cada llamada, o usar modelos premium para tareas simples de clasificación. Define un presupuesto máximo y elige el modelo más barato que cumpla.
🚀 Bonus nivel pro
🧠
Memoria de conversaciones: guardar el historial de mensajes en Sheets o Redis y pasarlo como contexto en cada nueva llamada. La IA recuerda lo que se habló antes y las respuestas son mucho más coherentes.
📱
Integración con WhatsApp/chatbots: conectar el webhook a Twilio o WhatsApp Business API. El mismo sistema de clasificación + respuesta IA funciona como chatbot en WhatsApp sin cambiar nada.
😊
Análisis de sentimiento: agregar un campo "sentimiento" al prompt de clasificación (positivo / neutro / negativo). Los mensajes con sentimiento negativo activan una rama de respuesta más empática y urgente.
🔗
Flujos híbridos IA + reglas + APIs: reglas gratis para el 70% de casos obvios, IA para el 25% ambiguo, APIs externas para acciones. El sistema más eficiente en costo y el más robusto en producción.
🎯
Respuestas personalizadas con contexto CRM: antes de llamar a la IA para generar la respuesta, consultar el CRM (HubSpot, Sheets) para saber el historial del cliente. La IA redacta sabiendo si es cliente nuevo, frecuente o en riesgo.
📊
Dashboard de calidad IA: una hoja de Sheets que muestra la distribución de categorías, tasa de confianza baja y casos escalados a humanos. Con el tiempo puedes mejorar los prompts basándote en los datos reales.

Entregable — Asistente IA Funcionando

Al terminar esta clase tienes un sistema que no sigue reglas fijas: analiza el lenguaje natural, entiende la intención y genera respuestas personalizadas. Eso es automatización inteligente.

✅ Checklist del entregable
  • ✓
    Nodo OpenAI (o HTTP Request) conectado y funcionando
    La llamada a la API devuelve respuesta. Las credenciales están configuradas en n8n. El nodo no da error 401 ni 429.
  • ✓
    Prompt de clasificación devuelve JSON válido
    El mensaje "quiero información sobre precios" devuelve {"categoria":"ventas","confianza":"alta",...} consistentemente. Probado 5 veces con el mismo input.
  • ✓
    Parseo y validación del output IA
    El nodo Code parsea correctamente el JSON. Un output inesperado de la IA cae en el fallback con categoria: "otro" en vez de romper el workflow.
  • ✓
    Switch enruta por la categoría correcta
    Un mensaje de ventas va al output 0, uno de soporte al output 1. Probado con mensajes de cada categoría.
  • ✓
    Respuesta personalizada generada por IA
    El email o mensaje generado menciona el nombre del cliente y hace referencia a su consulta específica. No es una respuesta genérica.
  • ✓
    Registro en Sheets de cada interacción
    Cada mensaje procesado genera una fila con: timestamp, nombre, email, mensaje, categoría IA, confianza y respuesta generada.
  • ✓
    Probado con 5 mensajes distintos
    Uno por categoría + un mensaje ambiguo. Todos clasificados correctamente o escalados al fallback con confianza baja.
