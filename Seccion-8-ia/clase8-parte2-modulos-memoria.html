Módulos de Memoria en IA

La IA sin memoria responde bien una vez. La IA con memoria aprende, recuerda y mejora cada interacción. Esta es la diferencia entre un chatbot y un asistente real.

🧠 El problema que resuelve la memoria

Cada llamada a la IA es, por defecto, completamente sin contexto

Los modelos de IA no recuerdan nada entre llamadas. Si el usuario pregunta "¿y cuánto cuesta?" después de haber dicho "me interesa el plan Pro", la IA no sabe de qué habla. La memoria es lo que conecta conversaciones, almacena preferencias y hace que la IA se comporte como si conociera al usuario.

🔁 Sin memoria vs con memoria — la diferencia real

Usuario: Me llamo Carlos, busco CRM IA: Claro, ¿qué tipo de CRM? Usuario: Algo económico IA: Hay muchas opciones... // No sabe quién es Carlos // No sabe que busca CRM // Contexto perdido

Tipos de Memoria

Cada tipo de memoria resuelve un problema distinto. Elegir el incorrecto es guardar todo sin poder encontrar nada, o olvidar lo que importa.

🗂️ Mapa completo — cómo se relacionan los tipos
// Analogía con la memoria humana Corto plazo = lo que tienes en mente ahora mismo → Variables en la ejecución actual del workflow → Se pierde al terminar el run Largo plazo = lo que recuerdas de hace semanas → Datos del usuario en Sheets / DB → Persiste entre sesiones indefinidamente Conversación= el hilo de la charla de hoy → Mensajes previos pasados a la IA como contexto → Ventana deslizante de N turnos recientes Vectorial = tu biblioteca de conocimiento → Documentos indexados por significado → "¿Qué sé sobre X?" → búsqueda semántica Resumen = el diario de lo importante → La IA resume lo que pasó para no exceder contexto → Balance entre memoria y costo de tokens
⚖️ Comparativa — cuándo usar cada tipo
TipoDuraciónDónde se guardaMejor paraCosto
⚡ Corto plazo1 ejecuciónVariables del nodo SetPasar contexto entre nodos del mismo run💚 Gratis
💾 Largo plazoPermanenteSheets / DB / AirtablePerfil del usuario, historial de acciones💚 Casi gratis
💬 ConversaciónSesiónArray en variable / RedisChatbots, soporte, asistentes interactivos💛 Tokens extra
🧬 VectorialPermanentePinecone / SupabaseRAG, base de conocimiento, documentos🔴 Moderado
📝 ResumenSesión largaVariable / DBConversaciones largas sin exceder contexto💛 Tokens resumen
💡
La mayoría de casos necesita combinar dos tipos: memoria de conversación (para el hilo actual) + memoria a largo plazo (para el perfil del usuario). Juntas dan la experiencia de "la IA me conoce".
⚠️
El contexto de los LLMs no es infinito. GPT-4 tiene ~128k tokens, Claude ~200k. Pasar demasiado historial sube el costo y puede degradar la calidad. Por eso existen los módulos de resumen.
Módulo 1 de 5

Memoria a Corto Plazo

El contexto que vive dentro de una sola ejecución del workflow. Nada persiste, pero dentro del run la IA tiene todo lo que necesita.

⚡
Memoria a corto plazo · In-execution context
Contexto que vive en el run actual
En el corto plazo, la memoria son simplemente las variables que construyes con nodos Set y pasas al prompt de la IA. El nombre del usuario, su intención, datos del trigger — todo lo que necesitas para dar contexto al modelo en esa ejecución específica, sin guardarlo en ningún lugar externo.
⚡ Dentro del run 🔧 Nodo Set 💬 Inyectado en el prompt 🆓 Sin costo extra 🗑️ Se pierde al terminar
⚙️ Cómo se implementa en n8n
// Paso 1: Webhook recibe datos del usuario { "nombre": "Carlos", "consulta": "busco un CRM económico", "historial_compras": "plan básico x2" } // Paso 2: Set construye el contexto contexto_usuario = " Nombre: {{$json.nombre}} Historial: {{$json.historial_compras}} Consulta actual: {{$json.consulta}} " // Paso 3: Se inyecta en el prompt prompt = "Eres un asistente de ventas. Contexto del usuario: {{contexto_usuario}} Responde a su consulta:"
🏢 Casos reales
🛍️
E-commerce: el pedido actual + historial del cliente se inyectan para que la IA dé recomendaciones personalizadas en ese momento
💬
Soporte: el ticket actual + el producto que compró + el plan se pasan como contexto para que la IA responda con precisión
📊
Análisis: los datos del reporte del día se pasan para que la IA genere el resumen con los números correctos de esa ejecución
Módulo 2 de 5

Memoria a Largo Plazo

Lo que la IA recuerda de ti entre sesiones. Preferencias, historial, nombre, plan, interacciones pasadas — persiste indefinidamente en una base de datos externa.

💾
Memoria a largo plazo · Persistent user profile
El perfil del usuario que vive entre sesiones
La IA no tiene memoria entre llamadas, pero tu workflow sí puede tenerla. Cada vez que el usuario interactúa, n8n lee su perfil de Sheets o una DB, se lo pasa a la IA como contexto, y al final actualiza el perfil con lo nuevo. La próxima vez, la IA ya "lo conoce".
💾 Persiste siempre 📊 Sheets / DB / Airtable 👤 Perfil del usuario 🔄 Leer → usar → actualizar
⚙️ El patrón completo — leer, usar, actualizar
// PASO 1: Identificar al usuario Webhook recibe: { user_id: "usr_123", mensaje: "..." } // PASO 2: Leer perfil de la DB Sheets READ: buscar fila donde user_id == "usr_123" Resultado: { "nombre": "Carlos", "plan": "pro", "interacciones": 14, "temas_previos": "CRM, facturación, API", "ultima_sesion": "2025-01-10" } // PASO 3: Construir prompt con el perfil system_prompt = " Usuario: Carlos (plan Pro, 14 interacciones previas) Temas que ya conoce: CRM, facturación, API No repetir lo básico — va directo al grano. " // PASO 4: Llamar a la IA con ese contexto HTTP Request → IA API → respuesta personalizada // PASO 5: Actualizar el perfil Sheets UPDATE: user_id = "usr_123" interacciones = interacciones + 1 ultima_sesion = {{$now}} temas_previos = temas_previos + ", integración"

🏢 Casos reales
🎓
Cursos online: el asistente sabe qué módulos completó el estudiante y adapta las explicaciones al nivel demostrado
🏥
Salud: el bot recuerda condiciones previas, alergias y medicamentos para dar respuestas seguras
🛒
E-commerce: "Carlos siempre elige envío express" — la IA proactivamente lo recomienda sin que lo pida
Módulo 3 de 5

Memoria de Conversación

El historial del chat que se pasa a la IA como contexto. La diferencia entre un chatbot amnésico y uno que entiende el hilo de la conversación.

💬
Memoria de conversación · Chat history buffer
El historial del chat como contexto de la IA
Los LLMs procesan conversaciones como un array de mensajes: roles "user" y "assistant" alternados. Al pasar los mensajes anteriores en cada llamada, la IA puede responder con coherencia al hilo de la conversación. n8n guarda y acumula este array entre llamadas del mismo usuario.
💬 Array de mensajes 👤 user / 🤖 assistant 🪟 Ventana deslizante 💾 Redis / Sheets 🔁 Multi-turno
⚙️ Estructura del historial de mensajes
// Formato estándar que aceptan todos los LLMs messages: [ { "role": "system", "content": "Eres un asistente de ventas de n8n Corp." }, { "role": "user", "content": "Hola, me llamo Carlos" }, { "role": "assistant", "content": "Hola Carlos, ¿en qué te puedo ayudar?" }, { "role": "user", "content": "¿Tienen plan gratuito?" } // ← aquí va la respuesta del asistente ]
⚙️ Implementación en n8n con Sheets
// Guardar historial en Sheets por session_id // LEER historial previo Sheets READ: donde session_id == "{{$json.session_id}}" → resultado: [{ role, content }, ...] // AGREGAR el nuevo mensaje del usuario const historial = resultado ?? []; historial.push({ role: "user", content: {{$json.mensaje}} }); // LLAMAR a la IA con el historial completo HTTP → IA API: messages: [system_prompt, ...historial] // GUARDAR la respuesta de la IA historial.push({ role: "assistant", content: respuesta_ia }); Sheets UPDATE: historial = JSON.stringify(historial)
🪟 Ventana deslizante — controlar el tamaño
// Si el historial crece demasiado → tokens caros // Solución: ventana deslizante de N últimos turnos const MAX_TURNOS = 10; // 5 intercambios const historialCompleto = cargarHistorial(); const historialRecortado = historialCompleto .slice(-MAX_TURNOS * 2); // ×2 = user+assistant // Siempre incluir el system prompt primero const mensajes = [ system_prompt, ...historialRecortado, { role: "user", content: nuevoMensaje } ]; // Para conversaciones muy largas → usar Resumen
Módulo 4 de 5

Memoria Vectorial

La base de conocimiento de la IA. Documentos, manuales, FAQs indexados por significado. La IA encuentra lo relevante aunque no uses las palabras exactas.

🧬
Memoria vectorial · RAG — Retrieval Augmented Generation
Búsqueda por significado en tu base de conocimiento
La memoria vectorial convierte documentos en vectores numéricos (embeddings) que representan su significado. Cuando el usuario pregunta algo, su pregunta también se convierte en vector y se buscan los fragmentos más similares semánticamente. Eso se pasa a la IA como contexto. La IA responde basada en TU documentación, no en su entrenamiento.
📐 Embeddings 🔍 Búsqueda semántica 📄 Documentos propios 🏛️ Pinecone / Supabase 🎯 RAG pattern
⚙️ El patrón RAG completo en n8n
// FASE 1: Indexación (se hace una vez) PDF / Docs de tu empresa → Split en chunks (fragmentos de ~500 tokens) → HTTP Request → OpenAI Embeddings API POST /v1/embeddings body: { "input": chunk_texto, "model": "text-embedding-3-small" } → devuelve: vector de 1536 dimensiones → Supabase / Pinecone: guardar vector + texto original + metadata // FASE 2: Consulta (por cada pregunta) Webhook: { pregunta: "¿Cuál es la política de reembolso?" } → Embed la pregunta: misma API de embeddings → Buscar similares: vector store devuelve top 3-5 chunks más cercanos → Construir prompt: "Contexto de la documentación: {{chunk_1}} {{chunk_2}} {{chunk_3}} Pregunta: {{pregunta}} Responde SOLO con el contexto dado." → IA responde con información de TU empresa, no inventada
🏛️ Opciones de vector store
OpciónVentajaIntegración n8n
SupabaseSQL + pgvector, gratis hasta 500MBHTTP Request + nodo nativo
PineconeMás rápido, hecho para vectorsHTTP Request
WeaviateOpen source, self-hostedHTTP Request
QdrantSelf-hosted, muy rápidoHTTP Request
🏢 Casos reales de RAG
📋
Soporte técnico: indexar manual del producto. El bot responde con información exacta de la documentación, no alucinaciones
⚖️
Legal / Contratos: indexar políticas y contratos. La IA responde sobre cláusulas específicas citando el documento
🏥
Salud: indexar guías clínicas. El asistente responde basado en protocolos oficiales, no en entrenamiento general
⚠️
RAG no es magia, es calidad de datos. Si tus documentos están desactualizados o mal redactados, la IA responderá con esa información incorrecta. La calidad del resultado depende directamente de la calidad de lo indexado.
Módulo 5 de 5

Memoria de Resumen

El truco para conversaciones largas sin explotar el contexto ni el presupuesto. La IA resume lo que pasó para recordar lo importante sin cargar todo el historial.

📝
Memoria de resumen · Summarization buffer
Comprimir el historial antes de que explote
Cuando el historial de conversación supera cierto límite de tokens, en vez de descartar los mensajes más antiguos, le pides a la IA que los resuma en un párrafo. Ese resumen reemplaza los mensajes originales. El contexto se mantiene comprensible pero compacto.
📝 Comprime historial 💰 Reduce costo de tokens 🧠 Mantiene coherencia 🔄 Automático en n8n
⚙️ Implementación — cuándo y cómo resumir
// Trigger: cuando el historial supera N tokens const tokens_estimados = historial.length * 4; // ~4 chars/token const LIMITE_TOKENS = 6000; IF tokens_estimados > LIMITE_TOKENS: // Pedir a la IA que resuma la conversación previa HTTP → IA API: messages: [{ role: "user", content: "Resume esta conversación en 3 frases manteniendo los puntos clave y los compromisos del asistente: {{historial_antiguo}}" }] → respuesta: "Carlos es cliente Pro. Preguntó sobre integraciones de pago. Le prometimos acceso a la API de Stripe." // Reemplazar historial antiguo con el resumen nuevo_historial = [ { role: "system", content: "Resumen previo: {{resumen}}" }, ...mensajes_recientes // últimos 4 turnos intactos ] // Resultado: contexto compacto + coherencia total
💰 Impacto en costos con resumen
Sin resumen — turno 20~8.000 tokens
Con ventana de 10 turnos~2.000 tokens
Con resumen acumulativo~800 tokens
📌 Cuándo usar cada estrategia
1-5
Menos de 5 turnos: pasar todo el historial sin resumen — simple y sin pérdida de información
5-20
5 a 20 turnos: ventana deslizante de los últimos 10 — equilibrio ideal entre costo y contexto
20+
Más de 20 turnos: resumen + últimos 4 turnos — conversaciones de soporte largas o sesiones extendidas

🏢 Casos de uso del agente completo
🎓
Tutor de aprendizaje: recuerda qué aprendió el estudiante, adapta la dificultad, no repite lo ya visto, cita los materiales del curso
💼
Asistente de ventas: conoce el historial del cliente, sabe qué propuestas le hicieron, busca en catálogo, personaliza la respuesta
🏥
Asistente médico: recuerda condiciones del paciente, historial de consultas, busca en protocolos clínicos indexados
🛒
Shopping assistant: recuerda preferencias, historial de compras, busca en catálogo, recomienda con contexto real
⚠️ Consideraciones al combinar memorias
  • →
    Orden importa: siempre system → perfil → resumen → docs → chat reciente → pregunta actual
  • →
    Relevancia sobre cantidad: 3 fragmentos vectoriales relevantes > 10 irrelevantes que confunden
  • →
    Costo crece con capas: empieza con corto + conversación, agrega vectorial solo cuando sea necesario
  • ✗
    No guardar datos sensibles en el historial: contraseñas, tokens o datos personales delicados nunca en el array de mensajes
Sección 9

Entregable y Bonus

Lo que debes construir, la comparativa final de módulos y el camino hacia sistemas de IA verdaderamente inteligentes.

✅ Entregable — agente con al menos 2 módulos de memoria
  • ✓
    Memoria a largo plazo funcionando
    Perfil del usuario en Sheets: se lee al inicio de cada conversación y se actualiza al final con los datos nuevos.
  • ✓
    Memoria de conversación multi-turno
    El historial de mensajes se mantiene entre llamadas. La IA recuerda lo que se dijo hace 3 turnos sin que el usuario lo repita.
  • ✓
    Ventana deslizante configurada
    El historial no crece infinitamente. Máximo N turnos pasados al modelo para controlar el costo de tokens.
  • ✓
    Prompt que integra todos los contextos
    Un solo prompt bien construido que combina perfil del usuario + historial reciente + instrucciones del sistema.
  • ✓
    Probado con 3 turnos de conversación
    Verificar que en el turno 3 la IA recuerde lo dicho en el turno 1 sin que el usuario lo repita.

🚀 Bonus — memoria avanzada
🔍
Memoria episódica: guardar eventos clave de la conversación con timestamp y tags (ej: "Cliente aceptó propuesta el 15/01"). La IA puede referirse a ellos en futuras sesiones.
🧩
Memoria de entidades: extraer y guardar automáticamente nombres, empresas, productos y fechas mencionados. La IA los conoce sin que el usuario los repita.
🗄️
Redis para sesiones activas: para alta concurrencia, guardar el historial de conversación en Redis en vez de Sheets — latencia de 1ms vs 500ms.
🔄
Memoria compartida entre agentes: múltiples agentes especializados comparten la misma base de conocimiento vectorial y el perfil del usuario, colaborando en la respuesta.
