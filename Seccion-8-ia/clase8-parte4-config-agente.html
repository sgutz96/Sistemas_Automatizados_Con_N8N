Configuración del Agente IA

Las 8 opciones del nodo AI Agent de n8n. Cada una controla un aspecto distinto del comportamiento del agente — desde cómo piensa hasta cómo procesa imágenes y datos en lote.

🎯 ¿Por qué importa configurar bien el agente?

Un agente mal configurado gasta tokens, se cuelga en loops o ignora el contexto correcto

Las opciones del AI Agent no son decorativas. Controlan el límite de razonamiento, la identidad del agente, la visibilidad del proceso y la capacidad de procesar archivos y datos masivos. Configurarlas correctamente es la diferencia entre un agente que funciona bien y uno que falla silenciosamente.

Opción 1 de 8

System Message

La instrucción más importante del agente. Define quién es, qué puede hacer, qué no puede hacer y cómo debe responder. Todo lo que no está aquí, el modelo lo inventa.

💬
System Message · Identidad del agente
El prompt que define todo el comportamiento
El System Message es el primer mensaje que recibe el LLM — el que establece las reglas del juego antes de cualquier interacción del usuario. Un System Message bien escrito hace que el agente sea preciso, consistente y predecible. Uno vago produce un agente errático.
🎭 Rol y personalidad 📋 Reglas de comportamiento 🚫 Lo que NO debe hacer 📐 Formato de respuesta 🌍 Idioma y tono
⚙️ Sistema Message en n8n — dónde configurarlo
AI Agent · Options
System Message
You are a sales assistant for n8n Corp. Your role: - Help users with CRM and lead questions - Answer using the available tools - Always respond in Spanish - Be concise and professional You must NOT: - Make up data not returned by tools - Discuss competitor products - Share internal pricing not in the docs
📋 Estructura de un System Message efectivo
// SECCIÓN 1: Identidad y rol "Eres un asistente de ventas de [Empresa]. Tu trabajo es ayudar al equipo comercial con consultas sobre leads y clientes." // SECCIÓN 2: Capacidades (qué SÍ puede hacer) "Puedes: - Consultar y actualizar la base de leads - Calcular métricas de ventas - Buscar en la documentación de productos - Notificar al equipo por Slack" // SECCIÓN 3: Restricciones (qué NO puede hacer) "NO debes: - Inventar datos no devueltos por las tools - Compartir información de otros clientes - Hacer promesas sobre precios o descuentos" // SECCIÓN 4: Formato y tono "Responde siempre en español. Sé conciso — máximo 3 párrafos. Usa datos concretos cuando los tengas." // SECCIÓN 5: Contexto dinámico (opcional) "Fecha actual: {{$now.toFormat('dd/MM/yyyy')}} Usuario: {{$json.nombre_usuario}}"
💡
Usa expresiones dinámicas en el System Message. Puedes inyectar {{$now}}, {{$json.nombre}} o cualquier variable del workflow. Así la IA siempre sabe la fecha actual, el usuario que pregunta y el contexto de la ejecución.
⚠️
Sin System Message el modelo usa sus defaults. Por defecto OpenAI/Claude responden como asistentes genéricos. Sin System Message, el agente puede responder en inglés, inventar datos o salirse del dominio del negocio.
Opción 2 de 8

Max Iterations

El límite de ciclos que puede hacer el agente. Cada iteración es: pensar → llamar tool → recibir resultado → pensar de nuevo. Sin límite, puede quedar en loop infinito.

🔁
Max Iterations · Límite de razonamiento
Cuántas veces puede razonar y usar tools antes de responder
El agente trabaja en ciclos: piensa, llama una tool, recibe el resultado, piensa de nuevo, puede llamar otra tool, etc. Max Iterations define cuántos de esos ciclos puede hacer. Si llega al límite sin responder, n8n para la ejecución y retorna un error. Protege contra loops y costos desbocados.
🔢 Default: 10 🛡️ Protege contra loops 💰 Controla costos ⏱️ Limita tiempo
⚙️ Cómo contar una iteración
// Cada "vuelta" del ReAct loop = 1 iteración Iteración 1: IA piensa → llama buscar_cliente(email) → recibe: { nombre: "Carlos", id: "123" } Iteración 2: IA piensa → llama obtener_deals(cliente_id: "123") → recibe: [{ deal: "Plan Pro", monto: 500000 }] Iteración 3: IA piensa → llama calcular(deal.monto * 0.15) → recibe: { resultado: 75000 } Iteración 4: IA piensa → respuesta final al usuario (sin tool call = última iteración) // Total: 4 iteraciones para esta tarea // Si Max Iterations = 3, falla en la 3ra
🎚️ Valores recomendados por caso de uso
Tipo de agenteMax IterationsRazón
Chatbot simple (FAQ)3-51-2 búsquedas máximo
Asistente con datos5-10Varias consultas posibles
Agente de ventas10-15Buscar + calcular + actuar
Agente de análisis15-20Múltiples fuentes de datos
Agente autónomo25-50Tareas complejas multi-paso

⚠️ Más iteraciones = más tokens = más costo. Calibrar según la tarea real.

⚠️
Loop infinito sin Max Iterations. Si el agente entra en un ciclo (busca → no encuentra → busca de nuevo → no encuentra...) sin límite, el workflow corre hasta agotar tiempo o dinero. Siempre setear un valor razonable. Con el default de 10 generalmente es suficiente.
Opción 3 de 8

Return Intermediate Steps

Hacer visible el razonamiento interno del agente. Cada tool call, cada resultado intermedio — todo disponible en el output del nodo para debugging y auditoría.

🪜
Return Intermediate Steps · Transparencia del razonamiento
Ver cada paso del pensamiento del agente
Con esta opción activada, el output del nodo AI Agent incluye no solo la respuesta final, sino también el detalle de cada iteración: qué tool llamó, con qué argumentos, qué resultado obtuvo y cómo usó ese resultado en el siguiente paso. Indispensable para debugging y construcción inicial de agentes.
🔍 Debugging 📋 Auditoría 🧠 Razonamiento visible OFF en producción
⚙️ Output con Intermediate Steps activado
// Output del nodo con la opción ON { "output": "Carlos tiene 3 deals abiertos por $1.5M", "intermediateSteps": [ { "action": { "tool": "buscar_cliente", "input": { "query": "Carlos" } }, "observation": { "id": "clt_123", "nombre": "Carlos" } }, { "action": { "tool": "obtener_deals", "input": { "cliente_id": "clt_123" } }, "observation": [ { "monto": 500000 }, { "monto": 750000 }, { "monto": 250000 } ] } ] }
📌 Cuándo activarlo y cuándo no
  • ✅
    Activar durante desarrollo — para ver exactamente qué tools está usando el agente y detectar si las descripciones están funcionando
  • ✅
    Activar para auditoría — si el cliente necesita saber qué hizo el agente paso a paso para cada decisión
  • ✅
    Activar para debugging — cuando el agente da respuestas incorrectas y necesitas entender por qué
  • ❌
    Desactivar en producción — aumenta el tamaño del output significativamente y puede exponer datos internos al usuario final
Opción 4 de 8

Automatically Passthrough Binary Images

Cuando el nodo anterior al agente produce una imagen (PDF renderizado, captura, foto), esta opción la pasa directamente al modelo de visión sin pasos intermedios.

🖼️
Passthrough Binary Images · Vision IA
Imágenes al modelo de visión sin configuración extra
Cuando el workflow procesa imágenes — capturas de pantalla, fotos de productos, páginas de documentos escaneados — y el nodo anterior al AI Agent genera datos binarios de imagen, esta opción automáticamente los adjunta al mensaje para que el LLM multimodal (GPT-4o, Claude 3) los procese y razone sobre ellos.
👁️ Modelos vision 📸 Fotos y capturas 📄 PDFs renderizados 🔄 Sin Set extra
⚙️ Flujos donde se usa
// Flujo 1: Analizar factura recibida por email Email Trigger (con adjunto PDF) → Nodo: Extract PDF page → imagen binaria → AI Agent (Passthrough ON) → LLM ve la imagen + prompt: "Extrae: proveedor, monto, fecha, número" → retorna JSON estructurado // Flujo 2: Clasificar foto de producto Webhook (recibe foto del cliente) → AI Agent (Passthrough ON) → LLM analiza la imagen + prompt: "¿Qué producto es? ¿Tiene daños visibles?" → retorna: { producto, estado, accion } // Flujo 3: Leer captura de pantalla de error Webhook (screenshot del error) → AI Agent (Passthrough ON) → LLM lee el texto en la imagen + prompt: "¿Qué tipo de error es? Categoriza el ticket" → retorna: { tipo, prioridad, resolucion }
⚠️ Consideraciones
🤖
Solo funciona con modelos multimodales: GPT-4o, Claude 3 Sonnet/Opus, Gemini Pro Vision. Con modelos de solo texto, el agente ignora la imagen.
💰
Las imágenes cuestan más tokens: una imagen de 1024×1024 puede costar 765 tokens en GPT-4o. Considerar el costo si el volumen es alto.
📦
Formato soportado: PNG, JPG, WEBP, GIF. El nodo anterior debe producir datos binarios, no una URL. Si viene como URL, usar HTTP Request para descargarla primero.
Opción 5 de 8

Tracing Metadata

Adjuntar metadatos de identificación a cada ejecución del agente. Esencial para observabilidad, trazabilidad y correlacionar ejecuciones con usuarios o sesiones específicas en plataformas como LangSmith o Langfuse.

🔬
Tracing Metadata · Observabilidad del agente
Etiquetar cada ejecución para rastrearla después
Tracing Metadata permite adjuntar pares clave-valor a cada llamada del agente. Esos metadatos aparecen en herramientas de observabilidad de LLMs como LangSmith, Langfuse o Helicone. Puedes identificar qué usuario generó qué respuesta, a qué sesión pertenece, de qué workflow vino y cualquier dimensión de análisis que necesites.
🏷️ Tags por ejecución 👤 ID de usuario 🔍 LangSmith / Langfuse 📊 Análisis de costos por usuario
⚙️ Metadatos típicos a adjuntar
// Configuración en el nodo Tracing Metadata: user_id: "{{$json.user_id}}" session_id: "{{$json.session_id}}" workflow: "agente-ventas-v2" environment: "production" customer: "{{$json.empresa}}" plan: "{{$json.plan}}" // En LangSmith/Langfuse verás: → Ejecuciones agrupadas por user_id → Costo total por customer → Latencia promedio por plan → Tasa de éxito por workflow → Qué tools usa más cada usuario
🏢 Casos de uso
💰
Billing por uso: rastrear cuántos tokens consume cada cliente para cobrar según uso real en modelos de precios variables
🐛
Debugging por usuario: cuando un cliente reporta un problema, filtrar en LangSmith por su user_id y ver exactamente qué pasó
📊
A/B testing de prompts: etiquetar con version: "prompt_v1" vs v2 y comparar métricas de calidad y costo
Opción 6 de 8

Auto-save Highlighted Data

Guardar automáticamente los datos que el agente identifica como relevantes durante la conversación, sin necesidad de configurar nodos de almacenamiento adicionales.

💾
Auto-save Highlighted Data · Persistencia automática
El agente guarda lo que considera importante
Cuando esta opción está activada, los datos que la IA "resalta" durante su razonamiento — entidades extraídas, decisiones clave, valores importantes — se guardan automáticamente en la memoria del workflow. Útil para capturar información sin necesidad de configurar un nodo Set + Sheets explícito por cada dato.
🏷️ Entidades detectadas 📝 Decisiones clave 🔄 Sin nodos extra 💡 Útil con memoria
⚙️ Cuándo es útil
✅
Extracción de entidades: el agente detecta nombres, fechas, montos y los guarda para usarlos en herramientas posteriores sin re-procesar
✅
Construcción de contexto incremental: en conversaciones largas, los hechos importantes se van acumulando sin necesidad de resumir manualmente
✅
Pipeline de datos con IA: el agente procesa texto no estructurado y destaca los campos relevantes que luego van a Sheets
📌 Relación con los módulos de memoria (Parte 2)
// Funciona como complemento a la memoria a largo plazo Sin auto-save: Agente detecta: cliente = "Carlos", monto = $500k → Solo en la respuesta final → Si quieres guardarlo: nodo Set + Sheets manual Con auto-save: Agente detecta: cliente = "Carlos", monto = $500k → Se guarda en highlighted_data automáticamente → Disponible para el siguiente nodo vía {{$('AI Agent').first().json.highlighted_data}} // Ideal para agentes de extracción de datos // que procesan documentos o conversaciones
Opción 7 de 8

Enable Streaming

La respuesta llega token a token en vez de toda de golpe. La diferencia entre una UI donde el texto "escribe" en tiempo real y una que espera 5 segundos y aparece todo junto.

⚡
Enable Streaming · Respuesta en tiempo real
Token a token para una experiencia como ChatGPT
Con Streaming activado, n8n recibe la respuesta del LLM token a token y la puede reenviar a la interfaz de usuario en tiempo real. El usuario ve el texto "escribiéndose" mientras el modelo piensa — exactamente como ChatGPT. Sin streaming, el workflow espera la respuesta completa antes de enviar cualquier cosa, lo que se percibe como lag.
🔤 Token a token 👁️ UX en tiempo real 📡 Websocket o SSE ⚡ Latencia percibida menor
⚙️ Cómo funciona el streaming en n8n
// Sin streaming (por defecto) Usuario envía mensaje ↓ n8n espera... ↓ n8n espera... (5-15 segundos) ↓ n8n espera... Respuesta completa → usuario la ve toda de golpe // Con streaming activado Usuario envía mensaje ↓ "H" → UI muestra "H" ↓ "Ho" → UI muestra "Ho" ↓ "Hola" → UI muestra "Hola" ↓ "Hola," → ... ↓ "Hola, encontré" → ... Respuesta completa al terminar // La latencia percibida es mucho menor // En n8n: usar con Respond to Webhook // que soporta SSE (Server-Sent Events)
📌 Cuándo usar Streaming
✅
Chatbots con UI propia: cuando construyes una interfaz de chat que muestra respuestas en tiempo real
✅
Respuestas largas: resúmenes, análisis de documentos — el usuario empieza a leer mientras el modelo termina de generar
❌
No usar en batch o reportes: si la respuesta se va a procesar con otros nodos después, el streaming no ayuda y complica el pipeline
❌
No usar con tools complejas: el streaming interrumpe el ciclo razonamiento→tool. Mejor desactivarlo si el agente usa múltiples iteraciones
Opción 8 de 8

Batch Processing

Procesar múltiples items con el agente en paralelo o en serie controlada. La solución cuando tienes 50 emails, 200 registros o 1000 tickets que analizar con IA.

📦
Batch Processing · Procesamiento masivo con IA
El agente procesa N items sin saturar la API
Cuando el nodo AI Agent recibe múltiples items (un array de emails, tickets, registros), Batch Processing controla cuántos procesa simultáneamente. Sin esto, todos los items se envían a la API de IA al mismo tiempo, lo que puede agotar el rate limit, generar errores 429 y elevar el costo de forma incontrolada.
🔢 Tamaño del lote ⏱️ Pausa entre lotes 📊 Procesar 100s de items 🛡️ Evitar rate limits
⚙️ Configuración de Batch Processing
// Opciones disponibles Batch Size: 5 ← items por lote Wait Between: 2000 ← ms entre lotes // Cómo funciona con 100 emails: Lote 1: emails 1-5 → procesar → esperar 2s Lote 2: emails 6-10 → procesar → esperar 2s ... Lote 20: emails 96-100 → procesar // Sin Batch Processing: 100 emails → 100 requests simultáneos a la API → Rate limit 429 → falla masiva // Con Batch Processing (5 items, 2s wait): 5 requests × 20 lotes = 100 procesados Tiempo total: ~40 segundos Sin un solo 429
📊 Valores recomendados según el modelo
Modelo IABatch SizeWait (ms)
GPT-4o mini (pago)10-20500
GPT-4o (pago)5-101000
Claude Haiku10-20500
Claude Sonnet5-101000
Cualquier plan free1-35000

Perfiles de Configuración

Las 8 opciones combinadas según el caso de uso. Copia el perfil que más se acerque a lo que estás construyendo y ajusta los detalles.

🤖 Perfil 1 — Chatbot de soporte al cliente
Responde preguntas frecuentes, busca en documentación y crea tickets. Conversación en tiempo real.
⚙️ Configuración
System Message✅ Definido
Max Iterations5
Return Intermediate StepsOFF
Passthrough ImagesOFF
Tracing Metadatauser_id, session_id
Auto-saveON
Enable StreamingON
Batch ProcessingOFF

Por qué esta config: Streaming ON para buena UX. Iteraciones bajas porque las consultas son simples. Auto-save para capturar el número de ticket o datos del cliente sin nodos extra. Streaming incompatible con muchas iteraciones de tools.

💼 Perfil 2 — Agente de ventas con datos y acciones
Consulta CRM, calcula métricas, notifica al equipo y crea tareas. Múltiples tools por sesión.
⚙️ Configuración
System Message✅ Rol + restricciones
Max Iterations15
Return Intermediate StepsOFF (prod) / ON (dev)
Passthrough ImagesOFF
Tracing Metadatauser_id, workflow, env
Auto-saveON
Enable StreamingOFF
Batch ProcessingOFF

Por qué esta config: Iteraciones altas para cubrir: buscar cliente → obtener deals → calcular → notificar → crear tarea. Streaming OFF porque el pipeline de tools interrumpiría el stream. Tracing para analizar qué consultas hace cada vendedor.

📄 Perfil 3 — Procesador masivo de documentos
Analiza 100+ documentos, facturas o emails. Extrae datos estructurados en lote.
⚙️ Configuración
System Message✅ Extracción exacta
Max Iterations3
Return Intermediate StepsOFF
Passthrough ImagesON (si son PDFs)
Tracing Metadatabatch_id, doc_type
Auto-saveON
Enable StreamingOFF
Batch ProcessingON — size: 10, wait: 1000ms

Por qué esta config: Batch Processing obligatorio para no saturar la API. Iteraciones bajas porque cada documento se procesa una vez sin tools complejas. Passthrough Images si los documentos son PDFs renderizados como imagen. Auto-save para capturar los campos extraídos.
